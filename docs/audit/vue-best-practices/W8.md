### [高] RebornTreeSelect：v-model 受控时 change 事件带出的是旧值
- 位置：`app/components/reborn/ui/reborn-tree-select/RebornTreeSelect.vue:212-217`（`emit` 在 215 行）
- 类别：数据流
- 依据：`references/component-data-flow.md`「`v-model`：赋值后立即需要新值时，用事件里的值」；项目已知约束「受控绑定下赋值后同步读到的仍是旧值，事件载荷要用本地新值」
- 现状：
  ```ts
  model.value = props.multiple ? keys : (keys[0] ?? null);
  emit("change", model.value);
  ```
  Vue 3.5 的 `useModel` 在父组件传了 `v-model` 时，`set` 只 emit `update:modelValue`，不改本地值，要等父组件下一轮渲染把 prop 传回来才更新。所以这里同步读到的 `model.value` 是**修改前**的值。最常见的写法 `<RebornTreeSelect v-model="v" @change="onChange" />` 里，`onChange` 收到的永远是上一次的值。点选、勾选、移除标签、清空（`clear()` 调用的也是 `updateValue([])`）都会受影响。不绑 v-model 时走本地更新，所以 demo 里看不出来。
- 改法：先算出新值存进局部变量，赋值和 emit 都用这个变量。
  ```ts
  function updateValue(keys: TreeKey[]) {
    if (isDisabled.value) return;
    const next = props.multiple ? keys : (keys[0] ?? null);
    model.value = next;
    emit("change", next);
    validate("change");
  }
  ```
- 影响：不改公开 API；修好之后 `change` 的载荷与文档描述一致。回归风险低。建议对同仓库其他「赋值后立刻读 `model.value` 再 emit」的组件也排查一遍（不在本分片）。

### [高] RebornTree：非受控模式下只要展开 / 收起过任一节点，scrollTo 的 autoExpand 就失效
- 位置：`app/components/reborn/ui/reborn-tree/RebornTree.vue:265`、`284`、`291-295`、`892-896`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Use `defineModel` for v-model」；Vue `useModel` 的本地模式语义
- 现状：
  ```ts
  const mergedExpandedKeys = computed(() => expandedKeysModel.value ?? innerExpandedKeys.value);
  function setExpandedKeys(keys) { internalExpandWrite = true; innerExpandedKeys.value = keys; expandedKeysModel.value = keys; }
  // scrollTo
  if (autoExpand && expandedKeysModel.value === undefined) {
    innerExpandedKeys.value = [...new Set([...innerExpandedKeys.value, ...ancestorKeys(entity)])];
  ```
  父组件没传 `expandedKeys` 时，`defineModel` 进入本地模式，`expandedKeysModel.value = keys` 会把本地值改成 `keys`。用户第一次展开或收起之后，`expandedKeysModel.value` 就再也不是 `undefined`，于是：① `scrollTo` 把非受控当成受控，跳过展开；② 就算写了 `innerExpandedKeys`，`mergedExpandedKeys` 也优先读模型值，写入不生效。结果是目标节点不在 `flatNodes` 里，`index < 0` 直接 return，滚动不发生，也没有任何提示。demo 里的 `scrollTo({ key: "group-25", autoExpand: true })` 目标是根节点，不需要展开父链，所以暴露不出来。
- 改法：受控判定改成看父组件有没有传这个 prop（与 `useModel` 内部的判定一致），写入统一走 `setExpandedKeys`：
  ```ts
  const instance = getCurrentInstance();
  /** 父组件是否传入了 expandedKeys：传了即受控，展开集合归外部所有 */
  function isExpandedControlled() {
    const raw = instance?.vnode.props;
    return !!raw && ("expandedKeys" in raw || "expanded-keys" in raw);
  }
  // scrollTo 内
  if (autoExpand && !isExpandedControlled()) {
    setExpandedKeys([...new Set([...mergedExpandedKeys.value, ...ancestorKeys(entity)])]);
    await nextTick();
  }
  ```
  本地模式下 `defineModel` 本身就能存非受控状态，`innerExpandedKeys` / `innerSelectedKeys` / `innerCheckedKeys` / `innerLoadedKeys` 这几份和模型值是重复的状态源，可以后续一并收敛（不收敛也不影响这条修复）。
- 影响：不改公开 API。非受控时 autoExpand 会多 emit 一次 `update:expandedKeys`（没有监听者，无副作用）。需要回归 demo「虚拟滚动」一节，以及 RebornTreeSelect（它以 v-model 方式传 `expanded-keys`，属于受控，行为不变）。

### [高] RebornTypewriter：SSR 时 immediate watch 在服务端启动定时器，打字完成后留下一个永不清理的 setInterval
- 位置：`app/components/reborn/ui/reborn-typewriter/RebornTypewriter.vue:150-156`、`82-84`、`104`、`158`
- 类别：SSR / 生命周期与清理
- 依据：`references/reactivity.md`「Clean up async effects」；Vue SSR 对 `immediate: true` 的 watch 会在服务端 setup 里同步执行回调，而服务端不执行 `onBeforeUnmount`
- 现状：
  ```ts
  watch(() => props.text, (newText) => { if (props.resetOnChange) handleTextChange(newText); }, { immediate: true });
  // typeText → timers.type = setTimeout(...)；打完后 startCursorBlink → setInterval(...)
  onBeforeUnmount(clearAllTimers);
  ```
  服务端渲染时，回调在 setup 中立即执行，`setTimeout` 链在 Node 进程里逐字跑完，然后 `startCursorBlink()` 起一个 530ms 的 `setInterval`（`showCursor` 默认为 true）。服务端不会卸载组件，这个 interval 会一直运行，并持有整个组件实例。每渲染一次带打字机的页面就多泄漏一个，服务端内存和 CPU 会持续上涨。
- 改法：动画只在客户端启动。初始播放放进 `onMounted`，watch 不再加 `immediate`：
  ```ts
  onMounted(() => handleTextChange(props.text));
  watch(() => props.text, (t) => { if (props.resetOnChange) handleTextChange(t); });
  ```
  这样服务端只输出空文本，客户端挂载后才开始打字，水合也一致。这个改法同时修掉下面中级条目里「resetOnChange 为 false 时初始文本不出现」的问题。
- 影响：不改公开 API；SSR 首屏 HTML 从「首字符」变成空，SEO 场景如需完整文本，可以另外加一个视觉隐藏的完整文本节点。回归风险低。

### [高] RebornWatermark：客户端在 setup 阶段就生成水印，SSR 水合时 style 不会被修补，水印在 SSR 页面上不显示
- 位置：`app/components/reborn/ui/reborn-watermark/RebornWatermark.vue:114-122`、`124-133`
- 类别：SSR / 生命周期与清理
- 依据：`references/reactivity.md`「Use `immediate: true` instead of duplicate initial calls」；Vue 水合只为事件监听等少数 prop 补 patch，`style` / `class` 不一致时只在开发环境告警，不会修正 DOM（`runtime-core` `hydrateElement`）
- 现状：
  ```ts
  watchEffect(() => { if (process.client) drawWatermark() })
  onMounted(() => { drawWatermark() })
  ```
  `watchEffect` 的首次执行发生在 setup 内。客户端水合前，`watermarkBase64` 已经是 data URL，而服务端输出的是 `background-image: url()`。水合时 style 不一致，Vue 不修补，DOM 保留空背景。随后 `onMounted` 再画一次，得到相同的字符串，ref 不触发更新，于是水印一直不显示，要等某个 prop 变化才出现。对水印组件来说这是功能失效。另外，setup 里画一次、`onMounted` 又画一次，属于重复的初始调用。
- 改法：只在挂载后绘制，依赖变化时重绘。用 `flush: 'post'` 的 `watchEffect` 一处搞定：服务端不执行，客户端第一次运行排在挂载之后。
  ```ts
  watchEffect(drawWatermark, { flush: "post" });
  // 删除 onMounted(drawWatermark) 与 process.client 判断
  ```
- 影响：不改公开 API。UniApp 端没有 SSR，不受这条影响，不需要同步。回归时需确认 demo 改 props 后会重绘。

### [高] ScrollIsland：在 computed 里调用 @vueuse/core 的 useColorMode，既泄漏监听，又会改写 html 上的 dark/light 类、覆盖站点主题
- 位置：`app/components/reborn/ui/scroll-island/ScrollIsland.vue:3`、`24`（模板 `62-63` 读取）
- 类别：组件边界 / 生命周期与清理
- 依据：`references/composables.md`「Keep DOM interaction and cleanup with its owning UI or composable」，组合式函数必须在 setup 中同步调用
- 现状：
  ```ts
  import { useColorMode } from "@vueuse/core";
  const isDark = computed(() => useColorMode().value == "dark");
  ```
  1. 每次求值都会新建一个 `useColorMode` 实例，内部有 `useStorage`（window `storage` 监听 + 自定义同步事件）、`usePreferredDark`（matchMedia 监听）和 `watch`。computed 求值时没有活动的 effect scope，这些监听和侦听器都不会随组件卸载清理。每挂载一次就泄漏一组，颜色模式每变化一次（computed 重新求值）又泄漏一组。
  2. vueuse 的 `useColorMode` 默认 `selector: 'html'`、`attribute: 'class'`、`storageKey: 'vueuse-color-scheme'`，挂载后会立即把 html 的 `dark` / `light` 类改成**它自己存储的值**（默认 `auto`，即系统偏好）。本站和使用方项目都用 `@nuxtjs/color-mode` 管理主题，键名不同。所以只要系统偏好与用户在站点上选的主题不同，比如系统浅色、站点选深色，渲染 ScrollIsland 就会把整站切回浅色。同时还会往 localStorage 写入 `vueuse-color-scheme`。
  3. `isDark` 读到的是系统偏好，不是站点主题，配色判断本身也不对。
- 改法：首选不在 JS 里判断主题：两种 gauge 颜色改成 CSS 变量，配合 `dark:` 变体定义，组件直接传 `var(--…)`。若必须在 JS 里读，就跟仓库其他组件一致（`app/components/common/demo-stage/DemoStage.vue:53`），在 setup 里调用一次 Nuxt 自动导入的 `useColorMode`，只读不写：
  ```ts
  const colorMode = useColorMode(); // @nuxtjs/color-mode，不改写 html
  const isDark = computed(() => colorMode.value === "dark");
  ```
- 影响：不改公开 API；需删除 `@vueuse/core` 的这处导入。回归：深色 / 浅色切换后，打开 ScrollIsland demo，站点主题应保持不变。

### [高] ShaderToy：dispose 不释放 WebGL 上下文和 ResizeObserver，demo 每切换一次着色器就多一个活动上下文
- 位置：`app/components/reborn/ui/shader-toy/rebornShaderToy.ts:511-516`、`261-288`（ResizeObserver 是局部变量，262 行）、`137-146`；`app/components/reborn/ui/shader-toy/ShaderToy.vue:59-61`；触发场景见 `app/components/reborn/examples/shader-toy/ShaderToyDemo.vue:297-298`
- 类别：生命周期与清理
- 依据：`references/composables.md`「side effects clean up with their owner」；SKILL.md 自检项「side effects clean up with their owner」
- 现状：
  ```ts
  public dispose(): void {
    this.pause();
    if (this.renderer.gl.canvas.parentElement) { this.renderer.gl.canvas.parentElement.removeChild(this.renderer.gl.canvas); }
  }
  ```
  卸载时只停了循环、移除了 canvas：WebGL 上下文没有 `loseContext`，Program / Geometry 没有 `remove()`，ResizeObserver 从未 `disconnect`（连引用都没保存）。浏览器对同时存活的 WebGL 上下文有数量上限（Chrome 约 16 个），要等 GC 才会回收。demo 用 `:key="selectedExample"` 让切换着色器时重新挂载，切换十几次后控制台会报 "Too many active WebGL contexts"，最早的上下文被强制丢失，同页其他 WebGL 组件可能随之黑屏。在文档站来回切页也会累积上下文。
- 改法：在类里保存 RO 与 rAF 句柄，dispose 时完整释放：
  ```ts
  private resizeObserver: ResizeObserver | null = null;
  private rafId: number | null = null;
  private animate = (): void => {
    if (!this.isPlaying) return;
    this.draw();
    this.rafId = requestAnimationFrame(this.animate);
  };
  public dispose(): void {
    this.pause();
    if (this.rafId !== null) cancelAnimationFrame(this.rafId);
    this.resizeObserver?.disconnect();
    this.program?.remove();
    this.geometry.remove();
    this.mesh = null;
    this.program = null;
    this.renderer.gl.getExtension("WEBGL_lose_context")?.loseContext();
    this.renderer.gl.canvas.remove();
  }
  ```
- 影响：不改公开 API；`rebornShaderToy` 类经 `index.ts` 的 `export *` 对外暴露，`dispose` 行为变得更彻底，dispose 之后不能再复用这个实例（原本也不能可靠复用）。配合下文「shaderCode 挂载后不响应」修好之后，demo 可以去掉 `:key` 重挂。

### [中] RebornScrollbar：滚动状态和默认插槽在同一个渲染作用域，每次 scroll 都整组件重渲染并重跑插槽（已知约束的根因）

- 现状：
  ```ts
  vertical.value = { active: true, size: thumbSize, offset: ... };   // 每次 onScroll 都赋新对象
  verticalTrackStyle.value = { top: ..., height: ... };
  ```
  这三个 ref 都在根模板里读取，赋新对象必然触发 RebornScrollbar 重渲染，`<slot />` 随之重新调用插槽函数；悬停进出（`hovering`）、滚动淡入（`scrolling`）也一样。使用方目前的规避办法是把重内容包进独立子组件（reborn-table 已这样做），这种写法不算问题。这条说的是源头：只要使用方往里塞的是渲染函数插槽或大块内容，就会逐帧重建。

  ```ts
  const bars = reactive({ y: { active: false, size: 0, offset: 0 }, x: { ... }, visible: false, dragging: null as "y" | "x" | null, yTrackStyle: {} });
  // update() 内：值不变就不写，变化时就地修改 bars.y.size 等字段
  ```
  ```vue
  <ScrollbarBars :state="bars" @track-down="onTrackMouseDown" @thumb-down="onThumbMouseDown" />
  ```
  父组件渲染时不再读取滚动几何，滚动、悬停只触发子组件更新，插槽不再重跑。
- 影响：不改公开 API（props / emits / expose 不变）；CSS 类名保持不变即可。改完后 reborn-table 等现有的规避写法仍然有效，可以保留。回归：拖拽 thumb、点击轨道、`verticalOffset`、`always`、静默滚动。

### [中] RebornTree：设置 height 且 virtual=false 时，scrollTo 仍按 itemHeight 换算，定位偏移
- 位置：`app/components/reborn/ui/reborn-tree/RebornTree.vue:901-925`（902 行的分支条件、912 行），`966`
- 类别：其他
- 依据：按源码行为核对（虚拟与非虚拟模式下行高来源不同）
- 现状：
  ```ts
  if (!container || props.height === undefined) { /* scrollIntoView 回退 */ }
  const itemTop = index * props.itemHeight;
  ```
  只有虚拟滚动时，行才被内联样式固定为 `itemHeight`（966 行）。`virtual: false` 加 `height` 时，滚动容器依然存在，行高由内容决定（switcher `size-6`、标题 `py-0.5` 等，与默认 28 不一定相等），而 `scrollTo` 仍走 `index * itemHeight` 的换算，节点越多偏差累积越大。`animated` 打开时还有行级过渡。
- 改法：分支改用 `!useVirtual.value` 判断；非虚拟模式按目标元素的实际位置计算，根容器带 `relative` 类，正好是 `offsetParent`：
  ```ts
  if (!useVirtual.value) {
    const el = container?.querySelector<HTMLElement>(`[data-key="${CSS.escape(String(key))}"]`);
    if (!el || !container || props.height === undefined) { el?.scrollIntoView({ block: "nearest", behavior: smooth ? "smooth" : "auto" }); return; }
    const itemTop = el.offsetTop; const itemHeight = el.offsetHeight;
    // 其余 align / offset 计算用 itemTop / itemHeight 替换 index * props.itemHeight / props.itemHeight
  }
  ```
- 影响：不改公开 API。需在文档 `scrollTo` 说明里删掉「普通模式按行高换算」之类的描述（如有）。

### [中] RebornTypewriter：resetOnChange=false 时初始文本永远不出现；暴露的 startTyping / startDeleting 不清理在途定时器
