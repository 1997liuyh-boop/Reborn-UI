### [高] RebornCascaderDemo：演练场 watch 的 getter 每次返回新数组，调任何一个参数都会清空已选值
- 位置：`app/components/reborn/examples/reborn-cascader/RebornCascaderDemo.vue:105-110`
- 类别：响应性
- 依据：`references/reactivity.md`「Watch correctly for reactive」：监听多个值要传数组形式的多个源；getter 返回的新数组每次都不相等。
- 现状：
  ```ts
  watch(
    () => [state.value.multiple, state.value.pathMode],
    () => { playgroundValue.value = state.value.multiple ? [] : undefined; },
  );
  ```
  这个 getter 依赖了 `state` 这个 ref 本身。`Playground` 改任意控件时发出的是一个新对象（`app/components/common/play-ground/Playground.vue:80`：`emit("update:modelValue", { ...props.modelValue, [key]: value })`），`state.value` 被整体替换，getter 重新执行，返回一个新数组。getter 形式的单一数据源只用 `Object.is` 比较新旧值，新数组永远不等于旧数组，回调每次都会执行。
  触发条件：在演练场里先选一个地区，再改尺寸、配色、占位文字、`max-tag-count` 等任意与模式无关的参数，已选值都会被清空，「当前值」回到「未选择」。注释写的是「multiple / path-mode 切换后才清空」，实际行为与之不符。照抄到业务代码里（父组件整体替换表单对象时）会出现同样的「莫名清空」。
- 改法：改成多源数组，Vue 会逐项比较，只有这两个值真的变了才回调：
  ```ts
  watch(
    [() => state.value.multiple, () => state.value.pathMode],
    ([multiple]) => {
      playgroundValue.value = multiple ? [] : undefined;
    },
  );
  ```
- 影响：只改演示，不涉及组件公开 API。`pnpm kb:build --only reborn-cascader` 需要重跑。回归：切换 multiple / path-mode 仍会清空，改其他参数时保留已选值。

### [中] RebornCalendarEventsDemo：每个日期格各挂一个 RebornContextMenu，一个月视图就是 42 个实例，常驻 336 个全局监听与 42 个 body Teleport
- 位置：
  - `app/components/reborn/examples/reborn-calendar/RebornCalendarEventsDemo.vue:84-97`（`date-cell` 插槽里逐格包 `RebornContextMenu`）
  - `app/components/reborn/examples/reborn-calendar/RebornCalendarEventsDemo.vue:49-54`（`dateMenu()` 每次渲染为每格新建菜单数组）
  - 组件侧行为：`app/components/reborn/ui/reborn-context-menu/RebornContextMenu.vue:660-669`（每个实例挂载即注册 6 个 document 监听、2 个 window 监听，含捕获阶段的 `scroll`）、`:802`（每个实例一个 `Teleport` 到 body）、`:634-640`（对 `items` 的深度 watch）
- 类别：性能 / 组件边界
- 依据：
  - `references/perf-avoid-component-abstraction-in-lists.md`：列表热路径里避免逐项挂重组件。
  - `references/composables.md`「Keep DOM interaction and cleanup with its owning UI」：右键交互属于整个日历，不属于每个格子。
- 现状：
  ```vue
  <template #date-cell="{ data, events: dayEvents }">
    <RebornContextMenu :items="dateMenu(data.day, dayEvents.length)" ...>
  ```
  月视图固定 6 行 × 7 列，共 42 个格子，就是 42 个右键菜单实例：
  1. 共 42 × 8 = 336 个全局监听常驻。页面上任何元素滚动（包括格内事项列表自己的滚动）都会让 42 个实例各排一次 `requestAnimationFrame`，每次 mousedown / click / keydown 也要依次跑 42 个处理函数（菜单未打开时都会提前返回，但调度开销照付）。
  2. 42 个 `Teleport` 各往 body 插入锚点节点。
  3. `dateMenu()` 在模板里调用，日历每次重渲染都给 42 个实例传新数组，触发 42 次 `normalizeItems` 与深度 watch。

  这是演示「右键管理事项」的唯一示范，使用者照抄到日历、表格等网格场景时，实例数会随格子数线性增长。
- 改法：整个日历只包一个菜单，右键时按命中的格子确定目标日期。格子上已经有 `data-event-day`（第 86 行），可以直接用：
  ```vue
  <script setup lang="ts">
  /** 右键命中的日期与当天事项数，决定菜单内容 */
  const menuDay = ref(today);
  const menuItems = computed(() =>
    dateMenu(menuDay.value, events.value.filter(e => e.date === menuDay.value).length),
  );
  /** 捕获阶段先记下命中的格子，菜单随后按最新 items 打开 */
  function onCellContextMenu(event: MouseEvent) {
    const cell = (event.target as HTMLElement).closest<HTMLElement>("[data-event-day]");
    if (cell?.dataset.eventDay) menuDay.value = cell.dataset.eventDay;
  }
  </script>

  <template>
    <RebornContextMenu :items="menuItems">
      <RebornCalendar ... @contextmenu.capture="onCellContextMenu">
        <template #date-cell="{ data, events: dayEvents }">
          <div :data-event-day="data.day" ...>…</div>
        </template>
      </RebornCalendar>
    </RebornContextMenu>
  </template>
  ```
  待确认：`RebornContextMenu` 触发区的 `contextmenu` 监听需在冒泡阶段（日历上的捕获监听先执行）；菜单定位在 `open` 后的双 rAF 里计算（`RebornContextMenu.vue:614-623`），`items` 同步更新后再打开不会错位。右键落在格子之外（工具栏、表头）时 `onCellContextMenu` 命中不到格子，应把 `menuDay` 置空、让 `menuItems` 返回空数组；组件对空 `items` 是否仍弹出空面板，待确认。
- 影响：只改演示，不改组件 API。根因之一是组件「挂载即注册全局监听」，与 W 分片对 `RebornSelectTrigger` 常驻监听的结论同类，建议组件侧也改成打开时才注册；但即使组件修好，逐格挂实例仍有 42 个 Teleport 与 42 份 watch，演示侧仍应改成单实例。回归：右键添加 / 删除、当天无事项时「删除事项」置灰、年视图。

### [中] RebornCheckboxDemo：三个勾选框共用一个标量 v-model，各配不同的 true-value / false-value，实际表现成互斥单选
- 位置：`app/components/reborn/examples/reborn-checkbox/RebornCheckboxDemo.vue:89-90`、`:295-314`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Use `v-model` only for true two-way component contracts」：一个 v-model 对应一份状态；`true-value` / `false-value` 描述的是单个勾选框的取值。
- 现状：
  ```vue
  <RebornCheckbox v-model="noticeValue" true-value="系统更新" false-value="系统不更新" label="系统更新" />
  <RebornCheckbox v-model="noticeValue" true-value="产品迭代" false-value="产品不迭代" label="产品迭代" color="info" />
  <RebornCheckbox v-model="noticeValue" true-value="活动通知" false-value="活动不通知" label="活动通知" color="success" />
  ```
  三个勾选框读写同一个字符串：勾上「产品迭代」后值变成 `"产品迭代"`，另外两个随之变成未勾；再把它取消，值变成 `"产品不迭代"`，三个全部未勾。结果既不是三个独立开关，也不是规范的单选组。本节描述是「让单个勾选框直接绑定业务文案」，演示出来的却是互相覆盖。照抄的人会以为这样能得到三份独立的设置。
- 改法：每个勾选框绑定自己的状态，回显三个值：
  ```ts
  /** 自定义真假值：三项各自独立，未选中时也写入具体文案 */
  const notices = ref({ system: "系统更新", product: "产品不迭代", activity: "活动不通知" });
  ```
  ```vue
  <RebornCheckbox v-model="notices.system" true-value="系统更新" false-value="系统不更新" label="系统更新" />
  <RebornCheckbox v-model="notices.product" true-value="产品迭代" false-value="产品不迭代" label="产品迭代" color="info" />
  <RebornCheckbox v-model="notices.activity" true-value="活动通知" false-value="活动不通知" label="活动通知" color="success" />
  ```
  如果本意是演示「多选一」，应改用 `RebornRadioGroup`，不要用勾选框模拟。
- 影响：只改演示与回显文案。文档 `content/2.components/**/reborn-checkbox.md` 若引用了这一段示例代码，需同步；重跑 `pnpm kb:build --only reborn-checkbox`。
