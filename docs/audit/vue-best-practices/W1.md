## 审查口径补充

1. **SSR 类问题在本站不复现。** `nuxt.config.ts:51-56` 把 `reborn/examples/**` 与 `reborn/configs/**` 全部设为 `mode: "client"`，`content/**` 里出现的本分片组件标签都在代码块中，所以本分片组件在文档站只在客户端渲染。SSR 条目的触发条件是"使用方把组件源码拷到开启 SSR 的 Nuxt 页面中直接使用"。组件以拷贝源码的方式分发（ComponentViewer 的 `componentFiles`），这是常见用法，因此 SSR 渲染直接抛错的定为高，水合不一致定为中。
2. 本分片大多是 Web 独有的特效组件（移植自 inspira-ui / aceternity 一类实现），只有 RebornAffix、RebornAlert 在 UniApp 端有同名组件，涉及两端的条目在「影响」中写明。
3. 下面两类写法在本分片普遍存在，属于全仓库统一取舍，没有逐条列出，建议汇总时统一决定是否批量调整：
   - 原始类型状态用 `ref()` 而不是 `shallowRef()`（`references/reactivity.md`「Always use shallowRef() instead of ref() for primitive values」）：34 个文件约 96 处。
   - 模板引用用 `ref<HTMLElement>()` 而不是 Vue 3.5 的 `useTemplateRef()`（`references/sfc.md`「Access DOM / component refs with useTemplateRef()」）：24 个文件约 26 处。引用用法本身出错的（如 M09）单独列出。
4. motion-v 的 `exit`、`AnimatePresence` 属于第三方库语义，只在导致 Vue 层面的后果（组件未解析、离场不生效、属性落到 DOM）时记录。
5. 少量非 Vue 层面的功能缺陷（H6、L17）在审查中被确认，类别标为「其他」顺带记录。

## 高

### [高] H1 AnimatedList：`while (true)` 轮播没有退出条件，卸载后永远运行
- 位置：`app/components/reborn/ui/animated-list/AnimatedList.vue:18`、`:20-42`、`:46-48`
- 类别：生命周期与清理
- 依据：`vue-debug-guides/reference/cleanup-side-effects.md`「Clear all setInterval and setTimeout calls in onUnmounted」；`SKILL.md`「side effects clean up with their owner」
- 现状：
  ```ts
  onMounted(startLoop);
  while (true) {
    displayedItems.value.shift();
    displayedItems.value.push({ node: notifications[nextIndex.value], id: `${nextIndex.value}-${Date.now()}` });
    await wait(props.delay);
  }
  ```
  `startLoop` 是永不返回的 async 函数，组件卸载后 `setTimeout` 链仍每隔 `delay` 推进一次，持续改写已脱离的响应式数组并持有插槽 VNode。站内 SPA 每进入一次 AnimatedList 文档页就多一条永久循环；`examples/animated-list/AnimatedListOverview.vue:5` 的注释已因此回避使用该组件。
- 改法：加卸载标记并让等待可取消：
  ```ts
  let disposed = false;
  let timer: ReturnType<typeof setTimeout> | undefined;
  function wait(ms: number) {
    return new Promise<void>((resolve) => { timer = setTimeout(resolve, ms); });
  }
  onBeforeUnmount(() => { disposed = true; clearTimeout(timer); });
  // 两个 while 的条件改为 !disposed，await 返回后再判断一次
  ```
  也可以改用 `useIntervalFn` 驱动"移出一条、推入一条"，作用域销毁时自动停止。
- 影响：不改公开 API。Overview 仍应保持现状（缩略图挂载后不卸载，禁止常驻循环）。回归风险低。

### [高] H2 AnimatedTestimonials：卸载清理的判断写反，autoplay 定时器永不清除
- 位置：`app/components/reborn/ui/animated-testimonials/AnimatedTestimonials.vue:25`、`:31-41`
- 类别：生命周期与清理
- 依据：`vue-debug-guides/reference/cleanup-side-effects.md`「Clear all setInterval and setTimeout calls in onUnmounted」
- 现状：
  ```ts
  onUnmounted(() => {
    if (!interval.value) {
      clearInterval(interval.value);
    }
  });
  ```
  只有"没有定时器"时才执行清理。`autoplay` 为 true 时 `setInterval(handleNext, props.duration)` 在卸载后继续运行并改写 `active`，每挂载一次泄漏一个。站内 demo 没开 autoplay，所以尚未暴露。
- 改法：去掉取反；更好的写法是在 setup 顶层用 `useIntervalFn(handleNext, () => props.duration, { immediate: false })`，再 `watch(() => props.autoplay, (on) => (on ? resume() : pause()), { immediate: true })`，一并解决 L02 中 autoplay 不响应的问题，句柄也不必放进 ref。
- 影响：不改公开 API；回归风险低。

### [高] H3 Focus：模板用了 `<Motion>`，但既没导入也没有全局注册，聚焦框失效

- 依据：`vue-debug-guides/reference/rendering-resolve-component-for-string-names.md`「Using string names causes components to render as HTML elements or fail silently」

### [高] H4 AppleCard：每张卡在挂载时就监听 window 的 Esc，任意一次 Esc 都会把轮播滚到最后一张
- 位置：`app/components/reborn/ui/apple-card-carousel/AppleCard.vue:33-45`、`:61-64`；`app/components/reborn/ui/apple-card-carousel/AppleCardCarousel.vue:55-66`
- 类别：生命周期与清理
- 依据：`references/composables.md`「Keep DOM refs, focus, and pointer handling with their owning UI」；`SKILL.md`「side effects clean up with their owner」
- 现状：
  ```ts
  function handleKeyDown(event: KeyboardEvent) {
    if (event.key === "Escape") handleClose();
  }
  onMounted(() => { window.addEventListener("keydown", handleKeyDown); });
  function handleClose() { open.value = false; onCardClose(props.index); }
  ```
  监听从挂载起一直存在且不判断 `open`。页面上任意一次 Esc（关闭文档站搜索框、其它弹层等）都会让轮播里每张卡依次调用 `onCardClose(index)`，`handleCardClose` 逐个 `scrollTo`，最后一次以最后一张卡为准，轮播被平滑滚到末尾，`currentIndex` 也被改成最后一张。
- 改法：只在打开时响应，并让关闭幂等：
  ```ts
  useEventListener(window, "keydown", (e) => {
    if (open.value && e.key === "Escape") handleClose();
  });
  function handleClose() {
    if (!open.value) return;
    open.value = false;
    onCardClose(props.index);
  }
  ```
- 影响：不改公开 API；回归点：打开卡片后按 Esc 仍能关闭并滚回该卡。

- 位置：`app/components/reborn/ui/container-scroll/ContainerScroll.vue:22`；`app/components/reborn/ui/images-slider/ImagesSlider.vue:84-100`（`:89` `new Image()`，`:100` 顶层调用）

### [高] H6 ImagesSlider：「下一张」越界判断差一，自动播放永远到不了最后一张
- 位置：`app/components/reborn/ui/images-slider/ImagesSlider.vue:116-126`（`:122`）
- 类别：其他
- 依据：非技能条目，属功能缺陷，顺带记录
- 现状：
  ```ts
  let target = currentIndex.value + 1;
  if (target >= loadedImages.value?.length - 1) {
    target = 0;
  }
  ```
  到倒数第二张时 `target === length - 1` 就被回卷为 0。下一张、自动播放、滑动、方向键都看不到最后一张，只有从第 0 张"上一张"回卷时才出现；2 张图时一直停在第 1 张。
- 改法：`currentIndex.value = (currentIndex.value + 1) % loadedImages.value.length;`
- 影响：不改公开 API；demo 中最后一张图会开始出现，属于预期修复。

### [中] M03 AnimatedList / BlurReveal / LineShadowText：在渲染之外调用插槽并缓存 VNode
- 位置：`app/components/reborn/ui/animated-list/AnimatedList.vue:14`、`:21`；`app/components/reborn/ui/blur-reveal/BlurReveal.vue:22-32`、`:57-70`；`app/components/reborn/ui/line-shadow-text/LineShadowText.vue:16-23`、`:31`
- 类别：插槽与透传
- 依据：`references/component-slots.md`（插槽内容应在渲染中消费）；Vue 运行时警告 `Slot "default" invoked outside of the render function`
- 现状：
  ```ts
  // AnimatedList（onMounted 内）
  const notifications = slots.default ? (slots.default()[0].children ?? []) : [];
  // BlurReveal（onMounted 内）
  watchEffect(() => { children.value = slots.default ? slots.default() : []; });
  // LineShadowText（setup 顶层）
  const children = slots?.default ? slots.default()[0]?.children : null;
  if (!content) throw new Error("LineShadowText only accepts string content");
  ```
  三处都在渲染函数之外执行插槽：开发环境报上述警告；拿到的是一次性快照，父组件更新插槽后不跟随（AnimatedList 完全不更新；BlurReveal 只在插槽里读到的响应式数据变化时重跑，换插槽结构不会更新；LineShadowText 的 `data-text` 阴影文字与正文不同步）。另外：
  - AnimatedList 依赖"插槽第一个节点是 v-for 片段"，直接写几个静态 `<Notification>` 时 `[0].children` 是组件的插槽对象，`.length` 为 undefined，列表什么都不显示。
  - AnimatedList 与 BlurReveal 的内容只在 `onMounted` 之后出现，SSR 输出空容器。
  - LineShadowText 在 setup 里 `throw`，插槽多放一个元素就让整棵子树渲染失败。
- 改法：
  - BlurReveal：在模板中直接遍历 `$slots.default?.() ?? []`（必要时用一个小渲染函数展平 Fragment），让插槽调用留在渲染上下文里。
  - AnimatedList：改为接收 `items` 数组，用作用域插槽 `#item="{ item }"` 渲染，由组件自己管理轮换窗口。
  - LineShadowText：新增 `text` prop 作为 `data-text` 来源（或在渲染中从插槽取文本），非字符串内容只给开发期警告，不要 throw。
- 影响：AnimatedList 改为 `items` + 作用域插槽会改变公开用法，需同步文档、demo 与知识库；LineShadowText 新增 prop；BlurReveal 不改 API。

### [中] M04 AnimatedTestimonials / StarField / Meteors：渲染期调用 `Math.random()`，SSR 水合不一致且重渲染即重新随机
- 位置：`app/components/reborn/ui/animated-testimonials/AnimatedTestimonials.vue:55-57`、`:74`、`:80`、`:88`；`app/components/reborn/ui/compare/StarField.vue:24-48`；`app/components/reborn/ui/meteors/Meteors.vue:17-22`
- 类别：SSR
- 依据：`vue-debug-guides/reference/ssr-hydration-mismatch-causes.md`（随机值导致两端渲染结果不同）；`vue-debug-guides/reference/template-functions-no-side-effects.md`
- 现状：
  ```vue
  <!-- Meteors -->
  left: `${Math.floor(Math.random() * (400 - -400) + -400)}px`,
  ```
  ```ts
  // StarField
  const stars = computed(() => Array.from({ length: props.starsCount }, (_, i) => ({ top: `${random(0, 100)}%`, ... })));
  ```
  服务端与客户端各算一次随机值，`style` 不一致，开发环境报水合 style mismatch，生产环境 Vue 不修补属性、保留服务端那份。随机值在渲染中生成，还会在重渲染时重算：Meteors 在 `count` 变化时、AnimatedTestimonials 在每次 `active` 切换时都给所有未激活卡片换一个新角度（后者可能是刻意的抖动效果，但应显式表达）。
- 改法：随机数据只在客户端生成一次并缓存，例如 `const meteors = shallowRef<MeteorStyle[]>([]); onMounted(() => { meteors.value = createMeteors(props.count); }); watch(() => props.count, (n) => { meteors.value = createMeteors(n); });`，StarField 同理；AnimatedTestimonials 在 `onMounted` 为每张卡生成一次角度存入数组，确需每次切换重新随机就在 `watch(active)` 里显式更新。
- 影响：不改公开 API；客户端挂载前这些装饰元素为空，可接受。

### [中] M05 AppleCard：直接写 `body.style.overflow`，卸载时不恢复、关闭时写死 auto
- 位置：`app/components/reborn/ui/apple-card-carousel/AppleCard.vue:47-53`
- 类别：生命周期与清理
- 依据：`vue-debug-guides/reference/cleanup-side-effects.md`；项目已有引用计数的全局滚动锁 `app/composables/useGlobalScrollLock.ts`
- 现状：
  ```ts
  watch(open, (newVal) => {
    if (newVal) document.body.style.overflow = "hidden";
    else document.body.style.overflow = "auto";
  });
  ```
  卡片打开时组件被卸载（浏览器后退、路由跳转），`open` 不再变化，`body` 永远停在 `overflow: hidden`，整页无法滚动。关闭时写死 `auto` 而不是恢复原值，会覆盖页面原有设置；`useGlobalScrollLock.ts` 的注释也说明给 body 设 overflow 会改变 sticky 的参照容器。
- 改法：
  ```ts
  const lock = useGlobalScrollLock();
  watch(open, (v) => (v ? lock.acquire() : lock.release()));
  onBeforeUnmount(() => lock.release());
  ```
- 影响：不改公开 API；回归点：打开/关闭卡片后页面滚动与侧栏 sticky 正常。

### [中] M06 AnimateGrid：只在挂载时为当时的卡片绑定监听，且用 classList 直接改 DOM
- 位置：`app/components/reborn/ui/animate-grid/AnimateGrid.vue:25`、`:27-36`、`:45-62`、`:71`
- 类别：生命周期与清理
- 依据：`vue-debug-guides/reference/template-ref-v-for-order.md`「Refs collected from v-for may not match source array order」；`references/composables.md`「Keep DOM interaction and cleanup with its owning UI」
- 现状：
  ```ts
  onMounted(() => {
    card.value?.forEach((el, i) => {
      const { isOutside } = useMouseInElement(el);
      const adjacentCards = adjacentCardItems(i);
      watch(isOutside, (isOutside) => { if (!isOutside) el.classList.add("card-raised-big"); ... });
    });
  });
  ```
  - 只为挂载时存在的卡片建立监听，`cards` 增加后新卡没有效果，被移除的卡仍被 watch 到组件卸载；相邻关系按 v-for ref 数组的下标计算，而该数组不保证与 `cards` 同序。
  - 每张卡一个 `useMouseInElement`，各自注册 window 上的 mousemove/scroll 监听，并对元素挂 ResizeObserver 与监听 `class`/`style` 的 MutationObserver；16 张卡就是 16 套，而组件自己改 class 又会触发这些观察器重新测量。
  - 通过 `classList` 改 DOM，Vue 不知道这些类；`cards` 以下标为 key，重排后高亮会留在错误的元素上。
- 改法：用响应式状态驱动类名：`const hoveredIndex = shallowRef<number | null>(null)`，卡片上 `@mouseenter="hoveredIndex = index"`、`@mouseleave` 走 200ms 防抖清空，`:class="{ 'card-raised-big': hoveredIndex === index, 'card-raised-small': adjacentSet.has(index) }"`，`adjacentSet` 用 computed 按 `hoveredIndex` 与实际列数计算（顺带去掉写死的 16 与 4 列）。
- 影响：不改公开 API；需回归 hover 抬升与 200ms 回落的观感。

### [中] M07 ColorPicker / ObjectColorInput：受控输入框每次 input 都回填规范化值，输入中途被覆盖

- 改法：事件改名为 `change`（或提供 `defineModel<File[]>("files", { default: () => [] })`），emit 时传副本 `[...files.value]`；过渡期可同时 emit 旧的 `onChange`。
- 影响：改公开事件名，需同步文档、demo 与知识库。

### [低] L15 RebornAlert：关闭后轮播仍在运行并 emit change；数据源引用一变即重置；宽度只随窗口重测
- 位置：`app/components/reborn/ui/reborn-alert/RebornAlert.vue:171-207`、`:234-243`、`:245-254`
- 类别：生命周期与清理
- 依据：`vue-debug-guides/reference/cleanup-side-effects.md`；`references/reactivity.md`（watch 源应只包含真正影响副作用的量）
- 现状：
  ```ts
  watch(() => [props.messages, props.direction, props.rows, props.interval, props.speed], () => {
    activeIndex.value = 0; startCarousel(); measureMarquee();
  });
  watch(show, (visible) => { if (visible) measureMarquee(); });
  ```
  - `show` 变 false 后内容被 RebornTransition 卸载（其 `destroy` 默认 true），`setInterval` 仍在跑并继续对外 `emit("change")`。
  - watch 以 `messages` 的引用为依赖：父组件用 computed 或 `map` 生成 `messages`（例如随语言或其它状态重算）时，每次重算都会把轮播打回第 0 条；反过来父组件原地 `push` 时不会触发，从 1 条变 2 条后计时器不会启动。
  - 跑马灯只在 window resize 时重测，容器因侧栏折叠等原因变宽时起点与时长不更新。
- 改法：`watch(show, (v) => { if (v) { startCarousel(); measureMarquee(); } else stopCarousel(); })`；watch 源改为 `() => [messageCount.value, props.direction, rowCount.value, props.interval, props.speed]`；跑马灯改用 `useResizeObserver(marqueeWrapperRef, measureMarquee)`。
- 影响：不改公开 API；关闭后不再触发 `change`。UniApp 端（`packages/uniapp-project/src/components/reborn-alert/RebornAlert.vue`）用 swiper 实现，不受本条影响，但关闭后是否仍 emit 建议一并核对。

### [低] L16 AppleCard / MultiStepLoader：浮层的挂载位置
- 位置：`app/components/reborn/ui/apple-card-carousel/AppleCard.vue:68`；`app/components/reborn/ui/multi-step-loader/MultiStepLoader.vue:119-130`
- 类别：SSR
- 依据：`references/component-teleport.md`「Teleport Overlays Out of Transformed Containers」；`vue-debug-guides/reference/teleport-ssr-hydration.md`
- 现状：AppleCard 使用 `<Teleport to="body">`，Nuxt 的 SSR 只支持传送到 `#teleports`，SSR 页面中使用会出现水合问题；MultiStepLoader 的 `fixed inset-0` 全屏层直接渲染在原位，放进带 `transform` / `filter` 的祖先（例如带动效的卡片）时只会覆盖该祖先而不是视口。
- 改法：AppleCard 改为 `to="#teleports"`；MultiStepLoader 用 `<Teleport to="#teleports">` 包住 Transition。
- 影响：不改公开 API。

### [低] L17 Dock / DockIcon / AnimatedTooltip：指针坐标基准不一致
- 位置：`app/components/reborn/ui/dock/Dock.vue:41-46`；`app/components/reborn/ui/dock/DockIcon.vue:22-32`；`app/components/reborn/ui/animated-tooltip/AnimatedTooltip.vue:40-44`
- 类别：其他
- 依据：非技能条目，功能缺陷顺带记录
- 现状：Dock 记录的是 `e.pageX` / `e.pageY`（含页面滚动），DockIcon 拿它与 `getBoundingClientRect()`（视口坐标）相减，页面纵向滚动后竖向 Dock 的放大中心整体偏移 `scrollY`。AnimatedTooltip 的 mousemove 用 `event.target`，鼠标移到浮出的提示框等子元素上时取到的是子元素的矩形，旋转角度跳变。
- 改法：Dock 改用 `clientX` / `clientY`；AnimatedTooltip 改用 `event.currentTarget`。
- 影响：不改公开 API。

### [低] L18 ImagesSlider：`<Transition>` 直接包裹 `<slot>`
- 位置：`app/components/reborn/ui/images-slider/ImagesSlider.vue:229-232`
- 类别：插槽与透传
- 依据：`references/component-transition.md`「Wrap a single element or component inside <Transition>」
- 现状：
  ```vue
  <Transition appear enter-active-class="transition-all duration-300 delay-300 ease-in-out" enter-from-class="opacity-0 -translate-y-10">
    <slot v-if="!isLoading" :current-index="currentIndex" />
  </Transition>
  ```
  使用方在默认插槽放多个根节点（如标题 + 按钮）时，Transition 收到片段，开发环境报警告且不执行进场动画。
- 改法：在 Transition 内加一层 `<div v-if="!isLoading">` 再放 `<slot>`。
- 影响：多一层 DOM，覆盖层布局需回归。

### [低] L19 AppleBlurImage：src 变化不重置模糊态；SSR 下可能错过 load 事件（待确认）
- 位置：`app/components/reborn/ui/apple-card-carousel/AppleBlurImage.vue:21-25`、`:31`、`:38`
- 类别：SSR
- 依据：`vue-debug-guides/reference/lifecycle-ssr-awareness.md`
- 现状：`isLoading` 只在 `@load` 时置 false，`src` 变化后不会回到 true，新图加载期间没有模糊过渡。SSR 页面中若图片在水合挂上 `@load` 之前已经加载完成（缓存命中），`load` 不会再触发，图片会一直保持 `blur-sm`。**待确认**：需要在开启 SSR 的页面、图片命中缓存的情况下验证 load 是否早于水合。
- 改法：`onMounted(() => { if (imgRef.value?.complete) isLoading.value = false; })`；`watch(() => props.src, () => { isLoading.value = true; })`。
- 影响：不改公开 API。
