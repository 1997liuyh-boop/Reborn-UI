### [高] RebornNoticeBar：水平模式调用 replay() 会抹掉 Vue 写入的内联动画时长，滚动随之停住

- 位置：`app/components/reborn/ui/reborn-notice-bar/RebornNoticeBar.vue:188-200`（replay）、`:119-126`（textStyle）、`:304-308`（文本节点的 class / style 绑定）、`:340-342`（动画类）
- 类别：模板
- 依据：`references/animation-class-based-technique.md`「用响应式的 class 绑定驱动动画，元素状态交给 Vue」；`references/component-transition.md`「用 key 让 Vue 把节点当作新元素」
- 现状：
  ```ts
  textRef.value.style.animation = 'none';
  void textRef.value.offsetWidth;
  textRef.value.style.animation = '';
  ```
  `animation` 是简写属性，赋空串等同于 `removeProperty('animation')`，会连带删掉 `textStyle` 写进去的 `animation-duration` 与 `animation-play-state` 两个内联长属性。`textStyle` 是带缓存的 computed，依赖不变时返回同一个对象，Vue 不会再 patch 这个 style（`runtime-dom` 的 patchStyle 只在新旧 style 引用不同时执行），于是只剩 `.animate-notice-bar-scroll { animation: notice-bar-scroll linear infinite }` 生效，时长回到初始值 0s，文字停在原位不再滚动。之后只有鼠标移入移出（`isPaused` 变化生成新对象）或重新测量改变了数值，时长才会被写回。
  触发条件：水平模式（默认方向）下由外部按钮或代码调用 `replay()`。演示页的重播示例绑在通知栏自身的 `@click` 上（`app/components/reborn/examples/reborn-notice-bar/RebornNoticeBarDemo.vue:208-213`），点击时鼠标正悬停在栏上，移出触发 `resume` 生成新样式对象，把时长补了回来，问题因此被掩盖。
- 改法：水平重播改用 key 重建文本节点，由 Vue 重新写入全部内联样式，不再直接改 DOM：
  ```ts
  /** 重播计数：作为水平文本节点的 key，自增即重建节点，CSS 动画从头开始 */
  const replayKey = shallowRef(0);

  // replay() 的水平分支
  replayKey.value++;
  ```
  模板：`<div v-else ref="textRef" :key="replayKey" ...>`。
- 影响：不改公开 API。UniApp 端 replay 是「重新测量并重启」的另一套实现（`packages/uniapp-project/src/components/reborn-notice-bar/RebornNoticeBar.vue:182-194`），不受影响。回归点：重播后文字从 `--scroll-distance` 起点重新滚入；悬停暂停 / 恢复不受影响。

### [高] RebornNoticeBar：Web 端 close 事件从不派发，文档与 UniApp 承诺的「点右侧图标关闭」不成立

- 位置：`app/components/reborn/ui/reborn-notice-bar/RebornNoticeBar.vue:56-61`（声明 close）、`:209-212`（handleClose 没有任何调用方）、`:321-325`（右侧图标没有点击处理）；对照 `packages/uniapp-project/src/components/reborn-notice-bar/RebornNoticeBar.vue:203-204, 310`；演示 `app/components/reborn/examples/reborn-notice-bar/RebornNoticeBarDemo.vue:214-220`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Emits: Explicit Events Up——声明出去的事件就是公开契约」
- 现状：
  ```vue
  <span v-if="slots['right-icon'] || props.rightIcon" :class="styles.icon()">
    <slot name="right-icon"><Icon v-if="props.rightIcon" :name="props.rightIcon" /></slot>
  </span>
  ```
  `handleClose` 定义了却从未被调用，`close` 永远不会触发；UniApp 端右侧图标是 `@tap.stop="handleClose"`。文档 Emits 表写的是「关闭通知栏时触发 / 通用」，「事件与方法」一节也写「监听 close 事件实现关闭」。演示里同时绑了 `@close="handleClose"` 与 `@click="handleClose"`，真正起作用的是后者，点通知栏任意位置都会关闭。只按文档监听 `@close` 的写法必然无效。
- 改法：与 UniApp 对齐，右侧 prop 图标点击时派发 close 并阻止冒泡，禁用态按 `handleClick` 同一口径拦截：
  ```vue
  <span v-if="slots['right-icon'] || props.rightIcon" :class="styles.icon()" @click.stop="handleClose">
  ```
  若希望插槽形式的图标不参与关闭，可只在 `props.rightIcon` 分支上绑定（UniApp 即如此）。
- 影响：行为变更：点右侧图标不再触发 `click`。需同步演示（`:208-213` 的重播示例恰好用「右侧图标 + @click」，关闭示例应去掉 `@click="handleClose"`）与文档「事件与方法」一节；UniApp 无需改动。

### [中] RebornNoticeBar：滚动与轮播状态靠零散 watch 命令式维护，运行时改 props 后失步

- 位置：`app/components/reborn/ui/reborn-notice-bar/RebornNoticeBar.vue:73-76`、`:130-155`（checkOverflow）、`:157-167`（startVerticalTimer）、`:222-251`（三个 watch）、`:253-259`（只监听 window resize）
- 类别：响应性
- 依据：`references/reactivity.md`「Prefer computed over watcher-assigned derived refs」「Keep source state minimal, derive everything」
- 现状：`shouldScroll` / `animationDuration` 是在 checkOverflow 里赋值的派生值，而 checkOverflow 只在 `text`、`direction` 变化与窗口 resize 时运行；轮播定时器的启停也分散在三个 watch 里：
  ```ts
  watch(() => props.text, () => { checkOverflow(); if (isVerticalScroll.value) { verticalIndex.value = 0; startVerticalTimer(); } });
  watch(() => props.disabled, (disabled) => { if (disabled) stopVerticalTimer(); else if (isVerticalScroll.value) startVerticalTimer(); });
  ```
  可复现的失步：
  1. 改 `speed` 不重算时长——演练场（`RebornNoticeBarDemo.vue:91-94` 用 `v-bind="state"`）里的速率滑杆拖动无效，直到窗口缩放；
  2. 运行时改 `scrollable=false` 或 `disabled=true`，`shouldScroll` 仍为 true，水平文字继续滚动（与文档「禁用后不再滚动」不符）；`wrapable` 从 true 改回 false 后不重新判定溢出，不再滚动；
  3. `text` 从多条变成单条或空数组时轮播定时器不停，每隔 interval 派发一次 `change(0)`，空数组时 `% 0` 派发 `change(NaN)`；
  4. 改 `interval` 不生效；
  5. 容器宽度变化（侧栏折叠、父级 flex 变化）不触发 window resize，溢出判断过期。
- 改法：只把测量结果作为源状态，其余全部派生，计时器生命周期交给一个 watch：
  ```ts
  /** 测量结果：文本是否溢出、文本与容器宽度（由 measure 写入） */
  const overflowing = shallowRef(false);
  const shouldScroll = computed(() =>
    overflowing.value && props.scrollable && !props.wrapable && !props.disabled && !isVerticalScroll.value);
  const animationDuration = computed(() => (textWidth.value + wrapperWidth.value) / props.speed);

  useResizeObserver(wrapperRef, measure);
  watch([() => props.text, () => props.wrapable], () => nextTick(measure));
  // 轮播定时器：只要「是否轮播 / 是否禁用 / 间隔」任一变化就重建
  watch([isVerticalScroll, () => props.disabled, () => props.interval], ([vertical, disabled]) => {
    stopVerticalTimer();
    if (vertical && !disabled) startVerticalTimer();
  });
  ```
  首次启动放在 `onMounted`；文本条数变化时把 `verticalIndex` 钳回 `[0, length - 1]`。暴露的 `checkOverflow` 保留为手动触发 measure。
- 影响：不改公开 API。UniApp 端同名文件 `:216-235` 是同一套 watch，需由 U 分片核对后同步修改。

### [中] RebornPopover / RebornPopconfirm：受控 open 初始为 true 时气泡不打开

- 位置：`app/components/reborn/ui/reborn-popover/RebornPopover.vue:17-30`（withDefaults 未给 open / defaultOpen 默认值）、`:76-77`、`:96-103`；`app/components/reborn/ui/reborn-popconfirm/RebornPopconfirm.vue:17`、`:86`、`:140`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Use defineModel for v-model」；项目已知规则「类型含 Boolean 的 prop 未传会被强转成 false，须写 `default: undefined`」
- 现状：
  ```ts
  const internalOpen = ref(props.defaultOpen ?? props.open ?? false);
  watch(() => props.open, (v) => { if (v !== undefined) internalOpen.value = v; });
  ```
  `open`、`defaultOpen` 都是 `boolean` 且没有 `default: undefined`，未传时被强转成 `false`，`??` 回落永远不会走到下一项；优先级也写反了（非受控初值排在受控值前面）。于是 `v-model:open="visible"` 且 visible 初始为 true 时，`internalOpen` 取到 `false`，watch 不是 immediate，气泡保持关闭而父组件认为已经打开。Popconfirm 固定传 `:default-open="defaultOpen"`（其默认值为 false，`:17`），`v-model:open` 初始为 true 时同样命中。UniApp 端写的是 `ref(props.open || props.defaultOpen)`（`packages/uniapp-project/src/components/reborn-popover/RebornPopover.vue:112`），受控值生效，两端初始行为不一致。
- 改法：
  ```ts
  const props = withDefaults(defineProps<PopoverProps>(), {
    // ……其余默认值
    // 含 Boolean 的属性必须显式给 undefined，才能区分「未传」与「传了 false」
    open: undefined,
    defaultOpen: undefined,
  });
  const internalOpen = shallowRef(props.open ?? props.defaultOpen ?? false);
  ```
  更彻底的做法是按项目规则改为 `defineModel<boolean>('open', { default: undefined })` 承接外部状态，`internalOpen` 只做非受控兜底。
- 影响：props 名不变；若改用 defineModel，`PopoverProps` 接口里的 `open` 字段会移到宏声明，导出类型有变化（Popconfirm 只引用了 `PopoverProps['ui']`，需确认外部无其他引用）。修复后与 UniApp 初始行为一致。回归点：Popconfirm 的受控 / 非受控两种写法、`default-open`、异步确认（loading）。

### [中] RebornPagination：total 变小导致当前页越界时不回写 v-model

- 位置：`app/components/reborn/ui/reborn-pagination/RebornPagination.vue:84-95`（totalPages / currentPage）、`:217-224`（clampPage）、`:264-268`（只监听 modelValue 与 pageSize）
- 类别：数据流
- 依据：`references/component-data-flow.md`「v-model: Predictable Two-Way Bindings」；`references/reactivity.md`「watchers 负责副作用，且要覆盖其全部输入」
- 现状：
  ```ts
  watch(modelValue, () => clampPage());
  watch(pageSizeModel, () => clampPage());
  ```
  `currentPage` 只在显示层钳到 `totalPages`。筛选后 total 从 100 变成 5、而当前停在第 10 页时，界面高亮第 1 页，但 `v-model` 仍是 10，也不派发 `current-change`，父组件继续按第 10 页请求，拿到空列表。
- 改法：`watch([modelValue, pageSizeModel, totalPages], clampPage)`。若业务在加载期 total 会短暂为 0，可在 `props.total > 0` 时才钳制，避免把页码拉回 1。
- 影响：total 变小时会多一次 `update:modelValue` + `current-change`（与 Element Plus 的行为一致），需在文档注明。UniApp 端 `:271-274` 同样只监听两项，建议同步。

### [中] RebornMenu：openedMenus 与 openKeys 两份展开状态，受控只读与 defaultOpeneds 场景下不同步

- 位置：`app/components/reborn/ui/reborn-menu/RebornMenu.vue:184-195`、`:269-273`、`:296`、`:509-518`、`:545-546`、`:584-586`、`:589-606`
- 类别：数据流
- 依据：SKILL.md「Keep state predictable: one source of truth, derive everything else」；`references/component-data-flow.md`「v-model: Predictable Two-Way Bindings」
- 现状：
  ```ts
  const openKeys = defineModel<MenuValue[]>("openKeys", { default: () => [] });
  const openedMenus = ref<MenuValue[]>(
    openKeys.value.length > 0 ? [...openKeys.value] : [...props.defaultOpeneds],
  );
  // handleOpen / handleClose / keepAncestorMenus / closeAllMenus 里都是先改 openedMenus，再
  openKeys.value = [...openedMenus.value];
  ```
  渲染读的是本地 `openedMenus`（经上下文下发给子菜单），`openKeys` 只是事后同步。① 只传 `:open-keys="keys"` 不接更新事件时（文档第 330 行称 `v-model:open-keys`「用于外部读取或控制展开集合」），点击照样展开 / 收起，受控值被绕过；② `v-model:open-keys` 搭配 `default-openeds` 时，界面已按 defaultOpeneds 展开，父组件拿到的 openKeys 却一直是 `[]`，直到第一次交互才同步。
- 改法：以 `openKeys` 为唯一状态源，`openedMenus` 改为只读派生：
  ```ts
  // 未给 openKeys 初值时用 defaultOpeneds 补上，并让父组件同步拿到
  if (!openKeys.value.length && props.defaultOpeneds.length) openKeys.value = [...props.defaultOpeneds];
  /** 当前展开集合：openKeys 的只读视图 */
  const openedMenus = computed(() => openKeys.value);
  ```
  所有写入点只写 `openKeys`；`openedMenuPaths` 保留为内部簿记，在 `watch(openKeys)` 里按新集合裁剪。
- 影响：props / emits 名不变。行为变更：只读绑定的 `:open-keys` 不再能被点击改动（变成真正受控）；挂载时用了 defaultOpeneds 会多派发一次 `update:openKeys`。需回归文档站侧栏 `app/components/docs/DocsAsideLeftBody.vue:244-262`（`v-model:open-keys` + `default-expand-all`）与文档里的受控示例。无 UniApp 同名组件。

### [中] RebornMenu：expose 的 open(index) 只传 [index] 作为路径，对嵌套子菜单无效

- 位置：`app/components/reborn/ui/reborn-menu/RebornMenu.vue:1034-1042`（expose）、`:572-587`（registerSubMenu 只在 shouldExpandAll 时记录路径）；`app/components/reborn/ui/reborn-menu/RebornSubMenu.vue:210-212`
- 类别：数据流
- 依据：`references/component-data-flow.md`「When a parent must call an exposed child method, expose only the intended API」——暴露的方法要能完成它声明的职责
- 现状：
  ```ts
  open: (index: string) => {
    handleOpen(index, [index]);
  },
  ```

- 改法：改为渲染期求值：`function inputAttrs() { const { style: _style, ...rest } = attrs; return rest; }`，模板 `v-bind="inputAttrs()"`。
- 影响：纯内部改动。

### [低] RebornMarquee：悬停暂停同时用了 JS 状态和 CSS group-hover，两套机制重复

- 位置：`app/components/reborn/ui/reborn-marquee/RebornMarquee.vue:27`、`:37-40`、`:58-63`；`app/components/reborn/ui/reborn-marquee/reborn-marquee.config.ts:38-43`
- 类别：响应性
- 依据：`references/reactivity.md`「Keep source state minimal」
- 现状：
  ```ts
  animationPlayState: props.pauseOnHover && isHovered.value ? 'paused' : 'running',
  ```
  config 已给 content 加了 `group-hover:[animation-play-state:paused!important]`，`!important` 永远压过内联值，`isHovered` 实际不起作用；它变化时还会让组件重渲染，默认插槽按 `repeat` 份重新执行一遍。根节点的 `group` 类也加了两次（config 一次、模板一次）。
- 改法：删掉 `isHovered`、mouseenter / mouseleave 与内联 `animationPlayState`，只保留 CSS 方案；去掉模板里多余的 `group`。
- 影响：纯内部改动。

## 已核实、不列为问题

- `useEventListener(window, …)`（`RebornMention.vue:422-423`、`RebornSubMenu.vue:649`）在 setup 里直接引用 `window`：Nuxt 的 SSR 构建通过 `@nuxt/vite-builder` 的 define 把 `window` 替换为 `undefined`，VueUse 遇到空目标不注册，服务端不会报错；文档站侧栏的 RebornSubMenu 经 SSR 正常输出也印证了这一点。
- `RebornMention.vue:133` 的 `computed(() => attrs.style)`：Vue 3.5 的 attrs 代理在 get 时追踪、更新时触发，可以正常更新（与第 22 条的「初始为空」边界情形不同）。
- `RebornMenuItem.vue:98-100`、`RebornSubMenu.vue:128-130` 在渲染期调用插槽取首字：写法正确，注释已说明原因。
- `RebornLoadingMask.vue` 使用 `<Transition>`：这是由 useLoading 管理生命周期的加载遮罩，依赖 afterLeave 卸载，不属于「弹层遮罩不要套 Transition」的情形。
- `RebornNotification.vue:220-223` 的 `v-html`：由 `dangerouslyUseHTMLString` 显式开启，与 Element Plus 同名约定一致。
- `RebornPopconfirm.vue:86` 的 `defineModel('open', { default: undefined })` 与 `onConfirm` 里 `await nextTick()` 再读 loading：符合项目已知规则。
