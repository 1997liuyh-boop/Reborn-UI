### [高] RebornPaginationDemo：「插槽定制」三个分页器共用 `slotPage`，但总页数不同，第三个分页器翻不过第 5 页
- 位置：
  - `app/components/reborn/examples/reborn-pagination/RebornPaginationDemo.vue:143`（`slotPage` 声明）
  - `app/components/reborn/examples/reborn-pagination/RebornPaginationDemo.vue:251`、`:266`（`:total="50"`，共 5 页）
  - `app/components/reborn/examples/reborn-pagination/RebornPaginationDemo.vue:284-285`（`:total="120"`，每页 10 条时共 12 页）
  - 组件侧的钳制逻辑：`app/components/reborn/ui/reborn-pagination/RebornPagination.vue:217-225`（`clampPage`）、`:265`（`watch(modelValue, () => clampPage())`）
- 类别：数据流 / 响应性
- 依据：`references/component-data-flow.md`「`v-model` 用于真正的双向契约」。每个 `v-model` 都是一份「组件可以回写」的契约，把同一个源绑给取值范围不同的几个组件，它们会互相改写对方的值。
- 现状：
  ```vue
  <RebornPagination v-model="slotPage" :total="50" background>   <!-- 5 页 -->
  <RebornPagination v-model="slotPage" :total="50">              <!-- 5 页 -->
  <RebornPagination v-model="slotPage" v-model:page-size="slotSize" :total="120" ...>  <!-- 12 页 -->
  ```
  每个 `RebornPagination` 都会在 `modelValue` 变化时执行 `clampPage()`：越界就写回 `modelValue.value = totalPages`，并派发 `current-change`。触发过程如下：
  1. 在第三个分页器上点第 8 页（或者在自定义跳页框输入 10 回车），`slotPage` 变成 8。
  2. 前两个分页器只有 5 页，它们的 watch 把值钳回 5，并通过 `update:modelValue` 写回 `slotPage`。
  3. 第三个分页器随即跳回第 5 页。

  所以第三个分页器的第 6 ~ 12 页、`#jumper` 插槽的跳转、把每页条数切到 5 之后的后半段页码，都无法停留。看起来就像组件坏了。如果把每页条数改成 20（共 6 页），第 6 页同样会被钳回 5。
- 改法：三个示例各用一份独立状态，例如 `const slotPagerPage = ref(3)`、`const slotArrowPage = ref(3)`、`const slotExtraPage = ref(3)`，分别绑定。如果想保留「联动」的观感，至少让三个分页器的 `total` 与 `page-size` 一致。
- 影响：只改演示，不涉及公开 API，也不需要同步 UniApp 端。`pnpm kb:build --only reborn-pagination` 会把演示代码收进知识库，改完要重新生成。

  - `app/components/reborn/ui/reborn-popconfirm/RebornPopconfirm.vue:17`（默认 `closeOnScroll: true`）、`:142`（原样透传给 popover）
- 类别：生命周期与清理 / 其他（缩略图约束）
- 依据：
  - METHOD.md「组件总览缩略图（`*Overview.vue`）挂载后不卸载」：缩略图只有一次挂载，状态一旦被改掉就回不来。
  - `references/component-data-flow.md`：默认展开只是初始状态，后续的关闭条件由组件的 props 决定，调用方要把不需要的关闭途径显式关掉。



- 影响：只改缩略图，不涉及公开 API。另外，`RebornPopover` 在 `onMounted` 里无条件挂 window 的 scroll / resize 监听（`RebornPopover.vue:323-326`），与缩略图约定「禁 window 滚动监听」冲突。这一点 W5「RebornSubMenu / RebornPopover：全局 scroll / resize 监听与打开状态无关、常驻」已经覆盖，修好那条后缩略图自动受益。

### [高] RebornPopoverDemo：「受控与手动关闭」的外部按钮用取反切换，气泡打开时点「外部关闭」会先被点击外部关掉、再被取反重新打开
- 位置：
  - `app/components/reborn/examples/reborn-popover/RebornPopoverDemo.vue:262-266`（`v-model:open="controlledOpen"`，`dismissible` 为默认 `true`）
  - `app/components/reborn/examples/reborn-popover/RebornPopoverDemo.vue:279-283`（`@click="controlledOpen = !controlledOpen"`）
  - 组件侧：`app/composables/useFloatingDismiss.ts:66-69`（在 document 捕获阶段监听 `pointerdown`，早于按钮自己的 `click`）、`app/components/reborn/ui/reborn-popover/RebornPopover.vue:105-111`（关闭时同步 emit `update:open`）、`:98-103`（父级再改 `open` 时同步回内部）
- 类别：数据流
- 依据：`references/component-data-flow.md`「`v-model` 是双向契约」。子组件会自己把 `open` 写回 `false`，父级就不能再假设「取反」能得到预期值。外部控制受控浮层时，要写目标值，不要取反。
- 现状：
  ```vue
  <RebornPopover ref="popoverRef" v-model:open="controlledOpen" placement="top"> ... </RebornPopover>
  <RebornButton :label="controlledOpen ? '外部关闭' : '外部打开'" @click="controlledOpen = !controlledOpen" />
  ```
  气泡打开时按下「外部关闭」，事件顺序如下：
  1. `pointerdown` 先到 document 捕获阶段的 `onPointerDown`。按钮不在气泡的 `elements` 里，被判定为点击外部，于是 `open = false`，同步 emit 后 `controlledOpen` 变为 `false`。按钮文案在本轮微任务里更新成「外部打开」。
  2. 松开后才派发 `click`，此时执行 `controlledOpen = !false`，结果为 `true`，气泡被重新打开。

  结果是这个按钮在气泡打开时永远关不掉它，只会让气泡闪一下。这一节的标题就是「受控与手动关闭」，演示的核心交互失效了。而「外部按钮切换受控浮层」正是业务里最常照抄的写法。
- 改法：外部按钮写目标值，不取反。拆成两个按钮最直观：
  ```vue
  <RebornButton variant="outlined" label="外部打开" :disabled="controlledOpen" @click="controlledOpen = true" />
  <RebornButton variant="outlined" label="外部关闭" :disabled="!controlledOpen" @click="controlledOpen = false" />
  ```
  如果一定要保留单个切换按钮，就要把按钮纳入浮层的「内部区域」（组件需要提供忽略元素的入口），或在这一例关掉 `dismissible`。同时在 DemoNote 里说明原因：点击外部关闭发生在 `pointerdown`，早于按钮的 `click`。
- 影响：
  - 只改演示，不涉及公开 API。
  - 同样的取反写法如果出现在其他浮层演示里（Tooltip、Dropdown 等，不在本分片），也要一并排查。
  - 组件层面可以考虑给 `useFloatingDismiss` 增加 `ignore` 元素列表，属于新增能力，需要另行评审。

  ```ts
  const timers = new Set<ReturnType<typeof setTimeout>>();

    timers.add(id);
  }
  onBeforeUnmount(() => timers.forEach(clearTimeout));
  ```

- 类别：性能 / 响应性
- 依据：
  - `references/reactivity.md`「Keep filtered/sorted derivations out of templates」：派生数据放进 `computed` 或常量，不在模板里现算。
  - `vue-debug-guides/reference/perf-props-stability-update-optimization.md`「保持 props 稳定」：每次渲染都新建的数组 / 对象会让子组件判定 props 已变而重渲染。
- 现状：
  ```vue
  <RebornTable :data="rows.slice(0, 3)" :columns="columns" aria-label="数据驱动报销明细" />
  <RebornTable :data="rows" :columns="localSortColumns" :default-sort="{ prop: 'amount', order: 'ascending' }" ... />
  ```
  演示根组件只有一个渲染函数。上面任何一个事件回显变量变化，根组件都会整体重跑，`rows.slice(0, 3)` 和 `{ ... }` 都会得到新引用。`shouldUpdateComponent` 因此判定这些表格的 props 已变，于是：
  1. 每张表重新走「树展开 → 排序筛选 → 分页 → 选择缓存」整条 computed 管线，重新生成全部单元格 VNode。
  2. 内容重绘后 `onUpdated` 触发 `doLayout`，下一帧读取所有列宽和表头高度，强制同步布局。

  按上面的位置统计，一次点击大约让二十多张表同时走完这一遍。这页本来就是全站最长的演示之一，在演练场里连续点几行就会感到迟滞（具体帧耗时**待实测**：需在前台标签页用 Performance 面板录一次「点击演练场表格行」，后台标签页会冻结 rAF，量不出来）。

  更要紧的是照抄风险：业务里把 `:data="list.filter(...)"`、`:data="list.slice(...)"` 直接写进模板，配合 `lazy` 时，`table.lazy.ts:73-75` 会在每次父级渲染时清空已加载的子节点缓存，已展开的懒加载行会重新请求。本演示的懒加载表用的是常量 `lazyRows`，所以没有中招，但同页其他表格示范的正是会触发它的写法。
- 改法：切片与配置对象都提到 script 里，保持引用稳定。随状态变化的改用 `computed`：
  ```ts
  /** 各示例共用的数据切片：只切一次，引用稳定，父级重渲染时表格不会被判定为数据变化 */
  const rows2 = rows.slice(0, 2)
  const rows3 = rows.slice(0, 3)
  const rows4 = rows.slice(0, 4)
  const rows5 = rows.slice(0, 5)
  const EMPTY_ROWS: TableRow[] = []
  const statusData = computed(() => (statusEmpty.value ? EMPTY_ROWS : rows3))
  const fluidData = computed(() => (fluidExpanded.value ? rows : rows2))
  /** 静态配置对象同样提成常量 */
  const localPagination: TablePagination = { pageSizes: [3, 5, 10], layout: 'total, sizes, prev, pager, next' }
  const amountAscending: TableSort = { prop: 'amount', order: 'ascending' }
  /** 含响应式字段的配置用 computed，只在依赖变化时换引用 */
  const remotePagination = computed(() => ({ ...localPagination, total: remoteTotal.value }))
  const tooltipOptions = computed(() => ({ placement: 'top', closeDelay: 100, arrow: tooltipArrow.value, disabled: tooltipDisabled.value, ui: { content: 'max-w-80' } }))
  ```
  文件里已有 `fixedRows`、`overflowRows`、`dragRows` 这样提前算好的数据，照同一写法补齐即可。可在「基础表格」一节的 DemoNote 里加一句：`data` 要传稳定引用，不要在模板里现切。
- 影响：只改演示，不涉及公开 API。知识库 `examples` 会收录这份演示，改后要重新生成。这是演示层面的写法问题；组件侧「父级重渲染即重新测量」的成本是否需要再收窄（例如只在列宽相关输入变化时测量），留给负责 `reborn-table` 的 W 分片判断。
