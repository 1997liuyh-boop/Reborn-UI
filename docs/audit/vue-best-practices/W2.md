### [高] RebornBadge：自定义 class 同时加在外层过渡容器和内层徽章主体上，盒模型类会生效两次

- 位置：`app/components/reborn/ui/reborn-badge/RebornBadge.vue:121`、`:122`、`:159`、`:160`
- 类别：插槽与透传
- 依据：`references/component-fallthrough-attrs.md`（透传属性要落到确定的目标元素上）；`vue-debug-guides/reference/inheritattrs-false-for-wrapper-components.md`「包装组件把属性明确交给一个目标元素」
- 现状：
  ```ts
  root: (opts?: any) => styles.root({ class: cn(opts?.class, uiOverrides.value.root, props.class) }),
  base: (opts?: any) => styles.base({ class: cn(opts?.class, uiOverrides.value.base, props.class) }),
  ```
  模板第 159 行把 `ui.root()` 交给 `RebornTransition`，经透传落到它内部的 `div.rb-transition`；第 160 行又把 `ui.base({ class: props.class })` 交给内层的 `<component :is="as">`。同一个 `class` 因此出现在两层嵌套元素上。`class="ml-2"` 实际左移 16px；`px-*`、`opacity-*`、`ring-*`、`translate-*` 这类类名也都会叠加，或者在外层多出一圈。只要使用方传入影响盒模型或透明度的类就会触发。站内 `app/components/reborn/examples/reborn-badge/RebornBadgeDemo.vue:242` 的 `class="px-1 py-0"` 已经让外层容器左右各多出 4px 内边距。
- 改法：只保留一处落点。UniApp 端的 `customClass` 只给主体（`packages/uniapp-project/src/components/reborn-badge/RebornBadge.vue:126`），建议 Web 端也只给主体：
  ```ts
  root: (opts?: any) => styles.root({ class: cn(opts?.class, uiOverrides.value.root) }),
  base: (opts?: any) => styles.base({ class: cn(opts?.class, uiOverrides.value.base, props.class) }),
  ```
  模板改成 `:class="ui.base()"`，不再重复传 `props.class`。确实要给外层容器加类时用 `ui.root`。
- 影响：props 名不变，但 `class` 的落点从两层都有变成只在主体上，需要同步改 `content/2.components/button/reborn-badge.md:163`（目前写的是「容器类名」）和 `:214`，以及知识库。和 UniApp 对齐。如果有人靠外层容器做布局（比如 `w-full`），要改成 `ui.root`。回归时检查 demo 和 RebornCascader 里的标签（那里用的是 `:ui`，不受影响）。

### [中] RebornCascader / RebornCascaderPanel / RebornCheckbox / RebornCheckboxGroup：受控绑定被外部改回 undefined 时，组件回落到内部残留值，清空不生效

- 位置：
  - `app/components/reborn/ui/reborn-cascader/RebornCascader.vue:186`（currentValue）、`:380`（updateValue 同时写 innerValue）、`:359`（setInputValue 同理）
  - `app/components/reborn/ui/reborn-cascader/RebornCascaderPanel.vue:107`、`:209`
  - `app/components/reborn/ui/reborn-checkbox/RebornCheckbox.vue:163`、`:290`
  - `app/components/reborn/ui/reborn-checkbox/RebornCheckboxGroup.vue:82`、`:148`
- 类别：数据流
- 依据：`vue-debug-guides/reference/define-model-default-value-sync.md`「父子值失步」；SKILL.md 核心原则「一个真实来源，其余派生」
- 现状：
  ```ts
  const currentValue = computed(() => model.value === undefined ? innerValue.value : model.value)
  function updateValue(value) { innerValue.value = value; model.value = value; /* … */ }
  ```
  组件用「`model.value` 是不是 undefined」来区分受控和非受控，而且受控时也会写 `innerValue`。触发条件是父级用 `const region = ref()` 加 `v-model="region"`：用户选中「浙江 / 杭州」后，业务代码执行 `region.value = undefined` 清空，此时 `model.value` 是 undefined，组件回落到仍然存着杭州的 `innerValue`，触发器继续显示旧值，而父级已经是 undefined。更糟的是用户再点同一项时，`RebornCascaderPanel.vue:218` 判断「没有变化」不提交，父级再也拿不到这个值。RebornCheckboxGroup 用的是 `??`，所以外部置 `null` 也会触发；RebornCheckbox 在 `true-value` 模式下同理。
- 改法：按「父级有没有传 modelValue」判断受控，受控时只读 `model`，只有非受控才写 `innerValue`。项目里已有同口径的写法（`app/composables/useFieldGroup.ts:358-359` 的 `hasExplicitSize`）：
  ```ts
  const instance = getCurrentInstance()
  /** 父级是否传了 modelValue：与 defineModel 判断「是否绑定」的口径一致 */
  function isBound() {
    const raw = instance?.vnode.props
    return !!raw && ('modelValue' in raw || 'model-value' in raw)
  }
  const currentValue = computed(() => (isBound() ? model.value : innerValue.value))
  function updateValue(value: CascaderValue) {
    if (!isBound()) innerValue.value = value
    model.value = value
    // …
  }
  ```
  RebornCascader 给面板传的是 `:model-value` 但没有监听 `update:modelValue`，按这个口径会判定为受控，读的正是父级下发的值，符合预期。`inputValue` / `popupVisible` 两组状态也照此处理。
- 影响：不改公开 API。UniApp 同名组件写法相同（`packages/uniapp-project/src/components/reborn-checkbox/RebornCheckbox.vue:110`、`:199`，`RebornCheckboxGroup.vue:62`、`:124`），需要同步修。回归重点是非受控的 `defaultValue` / `defaultChecked` 起始值，以及级联内嵌面板的选中回显。

- 位置：
  - `app/components/reborn/ui/reborn-cascader/RebornCascader.vue:115`、`:667`（根节点 RebornSelectTrigger）、`:495-506`（为绕开这个问题手动挂 focusin/focusout）
  - `app/components/reborn/ui/reborn-cascader/RebornCascaderPanel.vue:71`、`:492`
- 类别：插槽与透传
- 依据：`vue-debug-guides/reference/inheritattrs-false-for-wrapper-components.md`「设了 inheritAttrs: false 就必须把 $attrs 显式绑到目标元素」；`references/component-fallthrough-attrs.md`
- 现状：两个组件都声明了 `defineOptions({ inheritAttrs: false })`，但整份模板没有一处 `v-bind="$attrs"`。`class` 因为声明成了 prop 能生效，其余非 prop 属性一律被吞：`<RebornCascader style="width: 240px" id="region" aria-label="地区" data-testid="region">` 渲染出来什么都没有，`<label for="region">` 关联不上，E2E 选择器也找不到。RebornCascader 的根节点 RebornSelectTrigger 同样声明了 `inheritAttrs: false` 且没有回绑（`app/components/reborn/ui/reborn-select-trigger/RebornSelectTrigger.vue:10`），所以即使去掉 Cascader 这一行也会在下一层丢失。第 477-481 行的注释已经提到这一点，并用手动 `addEventListener` 绕开了焦点事件。
- 改法：

  - RebornCascader：需要先让 RebornSelectTrigger 把 `$attrs` 绑到它的根 wrapper（属于负责 reborn-select-trigger 的分片，需协同），再删掉 Cascader 的 `inheritAttrs: false`，属性就会经 RebornSelectTrigger 落到根节点。到时第 495-506 行的手动监听可以换成模板上的 `@focusin` / `@focusout`。
- 影响：不改 props / emits / slots。透传属性会开始真正生效；RebornSelect 等同族组件也是同样写法，建议一并处理。需要在文档注意事项里补一句「非 prop 属性落在哪个元素上」。

### [中] RebornCascaderPanel：懒加载把子节点直接写回 props.options，改的是父级数据，而且依赖它是深层响应式

- 位置：`app/components/reborn/ui/reborn-cascader/RebornCascaderPanel.vue:271-285`；依赖这次写回的地方：`RebornCascaderPanel.vue:112-118`、`app/components/reborn/ui/reborn-cascader/RebornCascader.vue:214-220`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Props: One-Way Data Down —— 子组件不要修改 props（含嵌套属性）」
- 现状：
  ```ts
  props.loadMore(node.raw, (children) => {
    if (children?.length) node.raw[childrenField] = children;
    else node.raw[props.fieldNames?.isLeaf ?? "isLeaf"] = true;
  ```
  `node.raw` 就是父级传进来的选项对象。两棵树（面板一棵、级联一棵）能否重建，全看这次写入能不能被追踪到。父级用 `shallowRef`、`markRaw` 或者模块级常量数组传 `options` 时（省市区这种大数据为了性能常这么写），懒加载回来的子节点永远不会出现：转圈结束了，但没有新的一列。文档 `content/2.components/input-and-forms/reborn-cascader.md:563` 已经要求 `options` 必须是 `ref` / `reactive`，但这只是把单向数据流的违例转嫁给了使用方。
- 改法：组件自己记懒加载结果，不再写调用方的对象：
  ```ts
  /** 懒加载回来的子节点，按节点 key 记账；树重建时优先取这里 */
  const loadedChildren = shallowReactive(new Map<string, CascaderOption[] | null>())
  ```
  给 `buildCascaderTree` 增加一个解析函数参数（如 `resolveChildren(raw, key)`），由它合并「原始 children ∪ 已加载 children」，并在结果为 `null` 时标记叶子。因为 RebornCascader 也要用同一份结果回显标签，建议和下面低级第 4 条一起做：由 RebornCascader 持有这棵树和懒加载缓存，通过内部 prop 交给面板；面板单独使用时自己持有。
- 影响：不改 props / emits。但行为会变：调用方的 `options` 不再被组件改写，原先靠「回读 options 拿到已加载子节点」的用法会失效。如需兼容，可以新增一个 `load` 事件抛出 `(option, children)`，或者暂时保留写回但不再依赖它。需要同步改文档第 135 行、第 563 行和知识库。UniApp 端的懒加载 API 不同（`lazyLoad`），不受影响。

### [中] RebornBreadcrumb：插槽模式下条目按 setup 先后登记，中途插入的条目会排到末尾，折叠时隐藏错项、视觉顺序错乱；SSR 首屏不折叠

- 位置：
  - `app/components/reborn/ui/reborn-breadcrumb/RebornBreadcrumb.vue:43-58`（登记表）、`:62-77`（折叠区间）、`:130`（省略号）
  - `app/components/reborn/ui/reborn-breadcrumb/RebornBreadcrumbItem.vue:39-56`（登记、取下标、order 样式）
- 类别：组件边界 / SSR
- 依据：`references/component-data-flow.md`「Provide/Inject：状态由提供方持有，契约要表达真实的不变量」；`vue-debug-guides/reference/lifecycle-ssr-awareness.md`
- 现状：
  ```ts
  function registerItem() { const id = ++idSeed; itemIds.value = [...itemIds.value, id]; return id }
  const index = computed(() => (context ? context.indexOfItem(itemId) : -1))
  ```
  下标等于 setup 的先后顺序，而不是条目在插槽里的位置。
  1. 写成 `<Item>首页</Item><Item v-if="showCat">分类</Item><Item>详情</Item>` 并设 `:max-count="2"`：`showCat` 变真时「分类」登记到末尾，登记表变成 [首页, 详情, 分类]。结果是该隐藏的「分类」显示了、「详情」被隐藏；「分类」的 `order` 是 4，排到视觉最后；分隔符靠 DOM 上的 `group-last/breadcrumb:hidden`（`reborn-breadcrumb.config.ts:65`）判断末项，与视觉末项对不上。带 key 的 `v-for` 往前或中间插入也一样。
  2. SSR 时父组件先渲染（这时还没有条目登记，`isCollapsing` 是 false，不渲染省略号），条目逐个 setup 时 `total` 只是「已登记个数」，于是首屏输出完整未折叠的路径，水合后才折叠，页面跳一下。客户端直接挂载时在同一次刷新里就完成了，看不到这个跳动。`routes` 模式下总数从数据就能拿到，不受影响。
- 改法：
  - 推荐：父组件在渲染时展开默认插槽（做法同 `reborn-avatar-group.utils.ts` 的 `flattenAvatarNodes`），按插槽顺序数出条目，用 `cloneVNode(node, { /* 内部 prop */ __index: i, __total: n })` 把下标和总数直接交给条目，并在正确位置插入省略号节点。这样既不需要登记表，也不需要 `order` 样式，SSR 首屏就是正确的折叠结果。注意渲染期只能读，不要写响应式状态（参见低级第 1 条）。
  - 最小改动：条目在 `onMounted` 时把根元素一起登记，父组件参照 `RebornAnchor.vue:136` 的 `sortLinks`，在条目挂载和自身 `onUpdated` 时按 `compareDocumentPosition` 重排。能修好顺序，但修不了 SSR 首屏的跳动。
- 影响：不改公开 API（推荐方案会给条目加一个下划线前缀的内部 prop）。UniApp 端是同一套登记表（`packages/uniapp-project/src/components/reborn-breadcrumb/RebornBreadcrumb.vue:43-62`），但小程序既不能用渲染函数也不能比较 DOM 先后，需要单独设计（例如条目显式传 `index`），两端内部实现会出现差异。

### [中] RebornAnchor：链接登记表变化后不会重新判定选中项，旧的选中状态会一直残留

- 位置：`app/components/reborn/ui/reborn-anchor/RebornAnchor.vue:383-386`、`:393-397`；登记入口：`app/components/reborn/ui/reborn-anchor/RebornAnchorLink.vue:40`、`:48-52`
- 类别：响应性
- 依据：`references/reactivity.md`「派生状态要随输入变化；副作用放进 watcher」
- 现状：
  ```ts
  watch([activeHref, links, () => props.type, () => props.direction, markerShape], async () => {
    await nextTick();
    updateMarker();
  });
  ```
  选中项只在挂载时和滚动事件里计算（`updateActive`）。`links` 变化时只重画标记，不重新判定。触发条件：`items` 异步到达、或者常驻布局里的锚点随路由换了一批链接，而这时容器没有发生滚动（已经在顶部、或者切页后滚动位置不变）。表现是 `activeHref` 仍指向旧链接：新链接里有同名 `href` 时会被错误高亮；没有同名时标记消失、任何链接都不高亮，`change` 也不触发，使用方拿到的选中状态是旧的，直到用户滚动一下才恢复。
- 改法：单独监听登记表，变化后按位置重新判定一次（复用现有的按帧合并，不会多做测量）：
  ```ts
  // 登记表变化（items 异步到达、换了一批锚点）后重新按位置判定选中项
  watch(links, () => nextTick(requestUpdateActive));
  ```
  `updateActive` 本身会跳过补间期间和点击落点，不会和点击定位冲突。
- 影响：不改 API；链接集合变化后可能会多触发一次 `change`，需要在文档注意事项里说明。

### [中] RebornAvatar：SSR 首屏的图片如果在水合之前就加载失败，error 事件会丢失，回退内容永远不出现

- 位置：`app/components/reborn/ui/reborn-avatar/RebornAvatar.vue:44`、`:63`、`:65-68`、`:76-78`
- 类别：SSR
- 依据：`vue-debug-guides/reference/lifecycle-ssr-awareness.md`「客户端接管前发生的事要在挂载后补偿」
- 现状：
  ```vue
  <img v-if="showImage" :key="imageKey" :src="src || undefined" … @error="handleError">
  ```
  回退完全依赖 `@error`。SSR 输出的 `<img>` 在 HTML 解析时就开始请求，地址无效（404、坏掉的 data URL）时 error 事件通常在 JS 下载执行、水合挂上监听之前就已经触发。水合不会补发，于是 `failed` 一直是 false：页面显示浏览器的破图标，图标和默认插槽的回退永远不出现，`error` 事件也不会抛给使用方。客户端路由切过来的页面不受影响。
- 改法：挂载时补查一次图片状态：
  ```ts
  const imgRef = useTemplateRef<HTMLImageElement>('img');
  onMounted(() => {
    const img = imgRef.value;
    // SSR 首屏：图片可能在水合挂上 @error 之前就已失败，此时 complete 为真且没有固有尺寸
    if (img?.complete && img.naturalWidth === 0) handleError(new Event('error'));
  });
  ```
  模板的 `<img>` 加上 `ref="img"`。待确认：没有固有尺寸的 SVG 头像在部分浏览器里 `naturalWidth` 也是 0，需要实测；如果会误判，改用 `img.decode().catch(...)` 判定。
- 影响：不改 API；补偿路径里 `error` 的载荷是新建的 `Event`，不是原始事件，需要在文档里说明。头像组里的头像会同时受益。

### [中] RebornCalendar：「今天」和不带时区的事项落格都在 setup 里按运行环境的时区计算，服务端和客户端不一致时水合错位，而且不会自己恢复

- 位置：`app/components/reborn/ui/reborn-calendar/RebornCalendar.vue:162`、`:165`、`:175`、`:214`、`:313-314`、`:329`、`:367`
- 类别：SSR
- 依据：`vue-debug-guides/reference/lifecycle-ssr-awareness.md`「客户端与服务端内容不一致要显式处理」
- 现状：
  ```ts
  const today = shallowRef(dayInZone(new Date(), zone.value));
  onMounted(refreshToday);
  ```
  没传 `timezone` 时 `zone` 是 undefined，服务端按服务器时区、客户端水合时按用户时区各算一次「今天」。比如服务器在 UTC、用户在 UTC+8，北京时间 0-8 点之间两端相差一天。未绑定 `v-model` 时视图月份也取自「今天」，月初、月末前后会算出两个不同的月份网格。带偏移的事项时间（`reborn-calendar.utils.ts:95-106` 的 `toDay`）同样按本地时区落格，两端可能落到不同的格子。Vue 水合时只修正文本，不修正 class，所以「今天」描边、`inMonth` 等类名会停在服务端的结果上。`onMounted(refreshToday)` 也救不回来：客户端 setup 时 `today` 已经是客户端的日期，`refreshToday` 比较后认为没有变化，不会触发更新。文档 `content/2.components/data/reborn-calendar.md:362` 写的「客户端挂载后立刻修正」与实际不符。
- 改法：水合前两端统一按服务端时区计算，挂载后再切回用户本地时区：

- 现状：布尔、数字、字符串状态都用 `ref`。`itemIds`、`activeKeys`、`loadingKeys`、`scrollTops`、`viewHeights`、`mainRootSize` 这些值每次都是整体替换，却用了深层 `ref`。RebornCarousel 的 `slideRefs` / `thumbRefs` 存放 DOM 数组，渲染里根本不读，却在每次渲染的 ref 回调里写入一个响应式数组。DOM 和组件引用用的是 `ref<HTMLElement | null>(null)`，而同分片的 RebornAnchor、RebornCalendar 已经用了 `shallowRef`。
- 改法：原始值和整体替换的集合改用 `shallowRef`；模板引用改用 `useTemplateRef`（仓库用的是 Vue 3.5.29）；`slideRefs` / `thumbRefs` 改成普通数组。
- 影响：无 API 变化。注意深层 ref 改成 shallowRef 后，任何就地修改（如 `.push`）都要改成整体替换，需要逐处确认。

### [低] RebornBackTop：defineEmits 用数组写法，事件没有类型

- 位置：`app/components/reborn/ui/reborn-back-top/RebornBackTop.vue:33-36`
- 类别：其他
- 依据：`references/component-data-flow.md`「TypeScript 项目用基于类型的 defineEmits」
- 现状：`const emit = defineEmits(["click"])`，同分片其余组件都是类型声明。
- 改法：`const emit = defineEmits<{ /** 点击按钮时触发，组件已先发起滚动 */ click: [] }>()`。
- 影响：无。UniApp 端同样是数组写法（`packages/uniapp-project/src/components/reborn-back-top/RebornBackTop.vue:24`），建议一并改。

### [低] reborn-cascader：纯函数模块用了 use 前缀命名

- 位置：`app/components/reborn/ui/reborn-cascader/useCascaderTree.ts`（全文件）；引用处 `RebornCascader.vue:34`、`RebornCascaderPanel.vue:24-29`
- 类别：其他
- 依据：`references/composables.md`「Keep Utilities as Utilities」
- 现状：文件里只有 `buildCascaderTree`、`findNodeByValue` 等纯函数和类型，没有任何响应式状态或生命周期，但 `use` 前缀会让人以为它是组合式函数（必须在 setup 里同步调用、带状态）。
- 改法：重命名为 `reborn-cascader.tree.ts`，与同分片的 `reborn-calendar.utils.ts`、`reborn-avatar-group.utils.ts` 命名一致。
- 影响：只影响内部 import，`index.ts` 没有导出这个模块。
