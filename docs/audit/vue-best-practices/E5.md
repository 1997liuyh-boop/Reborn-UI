### [高] ShaderToyDemo：切换示例用的 Select 系列组件在仓库里不存在，下拉框渲染成空的原生 select，三段着色器只能看到第一段
- 位置：
  - `app/components/reborn/examples/shader-toy/ShaderToyDemo.vue:304-319`（`<Select>` / `SelectTrigger` / `SelectValue` / `SelectContent` / `SelectGroup` / `SelectItem`）
  - `app/components/reborn/examples/shader-toy/ShaderToyDemo.vue:279-281`（`preset` / `selectedExample`）
  - `app/components/reborn/examples/shader-toy/ShaderToyDemo.vue:296-297`（`:key="selectedExample"`）
- 类别：模板 / 组件边界
- 依据：`docs/authoring/component-demo.md` §4「demo 中用到的每个 prop / 插槽 / 事件必须真实存在于组件实现」；`references/component-data-flow.md`「`v-model` 只用于真实存在的双向契约」。
- 现状：
  ```vue
  <Select v-model="preset">
    <SelectTrigger class="w-[220px]">
      <SelectValue placeholder="Select example shader" />
  ```
  这套写法来自 shadcn-vue，但本仓库没有这些组件：`app/` 下没有 `Select.vue` / `SelectTrigger.vue` 等文件，`.nuxt/components.d.ts` 里也没有注册（只有 `RebornSelect` / `RebornSelectTrigger`），`app/plugins/` 也没有全局注册。
  解析失败后，Vue 把它们当成原生标签渲染：
  1. `document.createElement('Select')` 在 HTML 文档里大小写不敏感，得到的是一个原生 `<select>`；`SelectTrigger` 等成为未知元素塞在它里面，没有 `<option>`，下拉框是空的。
  2. `v-model="preset"` 在原生标签上编译成 `modelValue` 属性和 `onUpdate:modelValue` 监听，原生 select 永远不会派发这个事件，`preset` 永远停在 `"starNest"`。
  3. 开发环境每次挂载都会报 6 条「Failed to resolve component」警告。
  这个 demo 挂在 `content/2.components/miscellaneous/shader-toy.md:9`，是 ShaderToy 文档页唯一的演示，打开即触发。另外 `:key="selectedExample"` 拿整段着色器源码（数 KB 的字符串）当 key，能用但不合适，重新挂载的意图用 `preset` 表达即可。
- 改法：换成仓库自己的组件，key 改用短标识：
  ```vue
  <script setup lang="ts">
  const presetOptions = Object.keys(shaderExamples).map(value => ({ label: getName(value), value }))
  </script>

  <ShaderToy :key="preset" :shader-code="selectedExample" class="h-full w-full" />
  <RebornSelect v-model="preset" :options="presetOptions" class="w-[220px]" />
  ```
  也可以用 `RebornRadioGroup type="button"` 平铺三个选项，切换更直观。顺手把 `getName` 里的对象提到模块顶层，`preset` 改 `shallowRef`。
- 影响：只改 demo，不涉及组件 API。改完需 `pnpm kb:build --only shader-toy` 重新生成知识库；文案（"Select Example:" 等英文）不在本次范围，可一并按 demo 规范改成中文。

### [中] SparklesFullPageDemo：在 computed 里调用 useColorMode()，每次重算都新建一套颜色模式状态，监听挂在组件作用域之外、卸载后不释放
- 位置：
  - `app/components/reborn/examples/sparkles/SparklesFullPageDemo.vue:5`
  - 对照：`app/components/reborn/examples/sparkles/SparklesDemo.vue:4-7`（同目录的正确写法，注释里已经写明原因）
- 类别：生命周期与清理 / 响应性
- 依据：`references/composables.md`「Keep related state, actions, and lifecycle cleanup together」——组合式函数要在 setup 顶层调用，才能把内部的副作用登记到组件作用域、随卸载清理。
- 现状：
  ```ts
  const particlesColor = computed(() => (useColorMode().value === "dark" ? "#FFFFFF" : "#000000"));
  ```
  `computed` 的 getter 在渲染时才求值，此时没有活动的组件实例与 effect scope：
  1. `useColorMode` 内部的 `onMounted` 等钩子注册失败，开发环境报「is called when there is no active component instance」。
  2. 它内部的 `useStorage` / `usePreferredDark` 会挂 `storage`、`matchMedia` 监听和 watcher，这些都登记不到组件作用域，卸载后不会释放。
  3. getter 依赖的是这次新建实例的内部 ref；切换一次亮暗模式，这个 ref 变化让 computed 重算，又新建一套实例、再挂一套监听。泄漏随切换次数累加。
  同目录的 `SparklesDemo.vue` 是对的写法，并在注释里说明了这一点；这个文件是遗留的旧写法。它目前没有被任何文档页引用，但文件名以 `Demo.vue` 结尾，会进知识库 `examples` 被照抄。
- 改法：与 `SparklesDemo.vue` 对齐：
  ```ts
  /** 须在 setup 顶层调用，内部监听才能随组件卸载释放 */
  const colorMode = useColorMode();
  /** 粒子颜色跟随亮暗模式 */
  const particlesColor = computed(() => (colorMode.value === "dark" ? "#FFFFFF" : "#000000"));
  ```
  如果这个全屏示例已经不需要，直接删除文件，避免继续进知识库。
- 影响：只改 demo。改动或删除后重新生成 `sparkles` 的知识库。

### [中] RebornTreeDemo / RebornTreeSelectDemo：在模板里现场创建 treeData / options，插槽所在组件每次重渲染都把一份新数据交给子组件，整棵树重建
- 位置：
  - `app/components/reborn/examples/reborn-tree/RebornTreeDemo.vue:537`、`547`（`DemoItem` 默认插槽；同一组件的 `#note` 插槽读 `singleSelectedKeys` / `multiSelectedKeys`，每次点选都会让 `DemoItem` 重渲染）
  - `app/components/reborn/examples/reborn-tree/RebornTreeDemo.vue:642`（`DemoBlock` 插槽里同时有 `RebornInput v-model="filterKeyword"`，每敲一个字都会让 `DemoBlock` 重渲染）
  - 同样写法、目前插槽所在组件没有响应式依赖、暂不触发的：`RebornTreeDemo.vue:469`、`490`、`602`、`610`、`618`
  - 同类但开销小：`app/components/reborn/examples/reborn-tree-select/RebornTreeSelectDemo.vue:122`（`:options="[{ label: '前端开发', value: 'web' }]"`，所在 `DemoBlock` 读 `selectValue`）
- 类别：性能 / 模板
- 依据：`references/reactivity.md`「Keep source state minimal, derive with computed」与「Avoid recomputing expensive logic in templates」；传给子组件的数据应有稳定的身份，不要在渲染路径里重新构造。
- 现状：
  ```vue
  <RebornTree
    v-model:selected-keys="singleSelectedKeys"
    :tree-data="makeTreeData()"
    selectable
  />
  <template #note>selectedKeys: [{{ singleSelectedKeys.join(", ") }}]</template>
  ```
  `makeTreeData()` 的注释写的是「每次调用返回全新副本，避免多个示例互相污染」，本意是每个示例一份，实际写在模板里就变成了每次渲染一份。
  `RebornTree` 用 `computed(() => buildTreeEntities(props.treeData, ...))`（`app/components/reborn/ui/reborn-tree/RebornTree.vue:208`）构建实体树，`treeData` 换了引用，实体表、拍平列表、勾选传导等派生全部重算，整棵树重新渲染。
  在 demo 里，点选一次、筛选框敲一个字，就会把对应那棵树完整重建一遍。树只有十来个节点，本站感觉不到；照抄到数据量大的页面，父组件任一状态变化都要整树重建。展开、选中这些状态按 key 保存，所以不会丢，问题只在性能。
- 改法：在 script 里为每个示例各建一份，模板只引用：
  ```ts
  /** 各示例各持一份树数据，避免互相污染，也保证引用稳定 */
  const basicTreeData = makeTreeData()
  const singleSelectTreeData = makeTreeData()
  const multiSelectTreeData = makeTreeData()
  const filterTreeData = makeTreeData()
  // …颜色示例同理：const colorTreeData = Object.fromEntries(treeColors.map(c => [c, makeColorTreeData()]))
  ```
  `RebornTreeSelectDemo.vue:122` 的选项数组同样提到 script 顶层常量。
- 影响：只改 demo，行为不变。改完重新生成 `reborn-tree`、`reborn-tree-select` 的知识库。

### [中] RebornUploadDemo：预览弹窗关闭后内容不卸载，autoplay 的视频继续在后台播放
- 位置：`app/components/reborn/examples/reborn-upload/RebornUploadDemo.vue:683-686`
- 类别：生命周期与清理
- 依据：`references/sfc.md`「Choose v-if vs v-show by toggle behavior」——带副作用的内容（播放中的媒体）在隐藏时要卸载或显式停止。
- 现状：
  ```vue
  <RebornDialog v-model="previewOpen" :title="previewFile?.name" width="640px" :cancel-btn="false" :confirm-btn="false">
    <video v-if="previewFile?.url && previewIsVideo" :src="previewFile.url" controls autoplay class="w-full rounded-sm" />
  ```
  `RebornDialog` 的 `destroyOnClose` 默认是 `false`（`app/components/reborn/ui/reborn-dialog/RebornDialog.vue:163`），关闭只是 `v-show` 隐藏（同文件 `:820`）。`<video>` 的 `v-if` 条件只看 `previewFile`，关闭弹窗后 `previewFile` 没清空，视频元素留在 DOM 里继续播放。
  触发条件：在「视频预览」小节（`:713-716`）或照片墙里选一个本地视频，点预览，再关掉弹窗。带音轨的视频会在弹窗消失后继续出声，直到播完。演示里用 canvas 现录的示例视频没有音轨、只有 2 秒，所以默认路径不明显。
- 改法：二选一。
  - 关闭即卸载：给弹窗加 `destroy-on-close`。
  - 保留复用：把条件改成 `v-if="previewOpen && previewFile?.url && previewIsVideo"`，或者 `watch(previewOpen, open => { if (!open) videoRef.value?.pause() })`。
  前者最省事，也最接近使用者照抄时的预期。
- 影响：只改 demo。

## 已核实不上报

下面这些写法看上去可疑，对照源码核实后确认在本分片的 demo 里不出错，或者问题在组件侧、不归本分片：

- **`RebornWatermarkDemo.vue:178-206` 的内联 `:gap` / `:content` / `:font` 字面量**：`RebornWatermark` 用 `watchEffect` 重绘画布（`app/components/reborn/ui/reborn-watermark/RebornWatermark.vue:114-118`），props 引用一变就重绘。但这两个水印直接放在 `DemoSection` 的默认插槽里，插槽内没有响应式读取，`DemoSection` 的 props 是静态字符串，演练场状态变化只会让根组件重渲染，不会让这两个插槽重跑，所以不会重绘。组件对 props 引用敏感、挂载时 `onMounted` 与 `watchEffect` 各画一次，属于 W 分片。
- **`ScrollbarDemo.vue:567`、`597` 每帧更新的滚动读数**：读取发生在 `:556` 那个 `DemoBlock` 的插槽里，滚动时只有这个 `DemoBlock` 重渲染，内部子组件的 props 不变、插槽稳定，不会连带重跑；`:504`、`:518` 的内联 `:style` 在别的 `DemoBlock` 里，不受影响。
- **`RebornTimePickerDemo.vue:295`、`304`，`RebornTreeSelectDemo.vue:123`、`160`、`172` 只传 `model-value` 不监听更新**：`defineModel` 在没有 `onUpdate:modelValue` 监听时会退回本地状态，交互正常，不是单向数据流问题。
- **`RebornTransferDemo.vue:541-549` 的 `:model-value="checked"` + `@change="toggle"`**：与组件自身默认插槽（`app/components/reborn/ui/reborn-transfer/RebornTransfer.vue:1226-1229`）写法一致，`toggle` 不接收参数，结果以父级重算的 `checked` 为准。
- **总览缩略图里的无限动画**：`RebornTypewriterOverview`、`SpinningTextOverview`、`SparklesOverview`、`RippleOverview`、`Text3dOverview`、`ReuiLaunchOverview` 用的都是 CSS 关键帧（作用于 `opacity` / `transform`），没有 JS 常驻循环；`RebornTransitionOverview`、`TextGenerateOverview`、`TextHighlightOverview`、`TextRevealOverview` 是挂载时播放一次的动画。缩略图都没有使用 WebGL，`ShaderToyOverview` 用纯 CSS 渐变近似。
- **`TracingBeamOverview.vue:40-45` 写死的渐变 id**：id 已经带了 `tracing-beam-overview-` 前缀，总览页只渲染一次，不会撞 id。组件 `TracingBeam.vue:127-133` 用的是通用 id `gradient`，同页多实例会撞，属于 W 分片。
- **`SafariMockupDemo.vue:3` 的 `src="/"`**：会在 iframe 里加载整站首页，偏重，但这是演示意图，不是 Vue 层面的问题。
