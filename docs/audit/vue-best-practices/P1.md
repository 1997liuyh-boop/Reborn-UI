### [高] 分页演示「先写数据、后判出错」：出错后重试或再次触底会重复拉取同一页，列表出现重复数据（Loadmore 还会出现重复 key）
- 位置：
  - `packages/uniapp-project/src/pages/reborn-loadmore/RebornLoadmoreDemo.vue:43-76`、`:58`、`:61-66`、`:73`、`:80-83`、`:125`
  - `packages/uniapp-project/src/pages/reborn-waterfall/RebornWaterfallDemo.vue:86-130`、`:88`、`:111`、`:114-119`、`:142-144`
- 类别：模板
- 依据：`references/sfc.md`「Always provide a stable `:key`」：key 必须唯一且稳定；两处都是会被照抄的分页范式
- 现状：
  ```ts

  if (list.value.length === 20 && !isError.value) {    // :61，再判定「出错」，return 时 page 没有 +1
    isError.value = true; state.value = 'error'; loading.value = false; return
  }
  function reload() { state.value = 'loading'; getList() }   // :80，重试仍按 page=2 计算 start=10
  ```
  - Loadmore 触发条件：页面滚到底两次（列表到 20 条）进入错误态，点 RebornLoadmore 的重试，`id` 11~20 被再次追加；模板 `v-for="item in list" :key="item.id"`（125）出现重复 key，H5 控制台报 Duplicate keys，小程序端 `wx:key` 重复，列表复用错位，第 11~20 条出现两遍。
  - Waterfall 同样先 `append` 再判出错（111、114），且守卫只拦 `loading` 与 `finished`（88），错误态下再触底（142）就重拉第 2 页，`id` 5~8 的卡片出现两份，点「广告」卡片的删除（`remove(id)`）会把两份一起删掉。

  ```ts
  setTimeout(() => {
    if (page.value === 3 && !isError.value) {   // 第 3 页首次请求失败
      isError.value = true
      state.value = 'error'
      loading.value = false
      return
    }
    list.value.push(...createPage(page.value))
    page.value++
    state.value = list.value.length >= 50 ? 'finished' : 'loading'
    loading.value = false
  }, 800)
  ```
  Waterfall 的重试入口见「中」第 1 条（`@click` 应为 `@reload`）。
- 影响：只改演示页；文档若引用了这两段 demo 代码需同步并重建知识库（`pnpm kb:build --only reborn-loadmore`、`reborn-waterfall`）。

### [中] RebornQrcodeDemo 的 Config* 子组件经可写 computed 直接改父级传入的对象，setter 从不执行
- 位置：
  - `packages/uniapp-project/src/pages/reborn-qrcode/components/ConfigBasic.vue:15-18`、`:26`、`:33`、`:42`
  - `packages/uniapp-project/src/pages/reborn-qrcode/components/ConfigShape.vue:15-18`、`:25`、`:34`、`:43`
  - `packages/uniapp-project/src/pages/reborn-qrcode/components/ConfigLogo.vue:12-15`、`:64`、`:78`、`:91`、`:98`
  - `packages/uniapp-project/src/pages/reborn-qrcode/components/ConfigColor.vue:10-13`、`ConfigBackground.vue:10-13`、`PreviewSection.vue:17-20`（同样的 get/set，只读不写，setter 是死代码）
- 类别：数据流
- 依据：`references/component-data-flow.md`「Props: One-Way Data Down」「Use `defineModel` for v-model in Vue 3.4+」；项目规则「双向绑定用 defineModel」
- 现状：
  ```ts
  const qrConfig = computed({
    get: () => props.modelValue,
    set: (val) => emit('update:modelValue', val),   // 只有整体赋值才会走到这里
  })
  ```
  ```vue
  <RebornTextarea v-model="qrConfig.text" />                 <!-- ConfigBasic:26 -->
  <view @tap="qrConfig.logoSize = item.value">               <!-- ConfigLogo:64 -->
  <switch @change="(e: any) => qrConfig.logoShadow = e.detail.value" />   <!-- ConfigLogo:91 -->
  ```
  模板里改的都是 `qrConfig.xxx`，等于直接改 `props.modelValue` 指向的父级响应式对象；`update:modelValue` 一次也不会发出，Vue 对深层改写也不告警。照抄这套写法时，父级若改用 `shallowRef`、冻结对象或在 `@update:model-value` 里做校验 / 持久化，子组件的修改会静默失效或绕过父级逻辑。
- 改法：子组件统一用 `defineModel`，字段级修改通过整体替换发出：
  ```ts

  const qrConfig = defineModel<QrConfig>({ required: true })
  function patch<K extends keyof QrConfig>(key: K, value: QrConfig[K]) {
    qrConfig.value = { ...qrConfig.value, [key]: value }
  }
  ```
  ```vue
  <RebornTextarea :model-value="qrConfig.text" @update:model-value="patch('text', $event)" />
  <view @tap="patch('logoSize', item.value)">
  ```
  `QrConfig` 类型从 `RebornQrcodeDemo.vue:28-53` 的字面量提取到同目录的 `types.ts`，同时去掉各处 `modelValue: any`。
- 影响：只改演示页；回归点是六个配置页签的每个控件都要确认仍能驱动预览（依赖「高」第 1 条先修好标签栏）。

