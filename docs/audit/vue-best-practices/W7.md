### [高] RebornTransfer：`isDisabled` 计算属性读取自身，禁用一次后再也解除不了
- 位置：`app/components/reborn/ui/reborn-transfer/RebornTransfer.vue:93`；`app/components/reborn/ui/reborn-transfer/RebornTransfer.vue:1068-1076`
- 类别：响应性
- 依据：`references/reactivity.md`「Keep computed getters pure」：计算属性只从源状态派生，不读自己
- 现状：
  ```ts
  const isDisabled = computed(() => !!formDisabled.value || isDisabled.value);
  ```
  getter 里重入读取自己时，3.5 的 `refreshComputed` 因为 `globalVersion` 相同直接返回上一次的 `_value`。所以表单禁用值为假时，结果就是上一次的结果：初次是 `undefined`，只要曾经变成 `true`，之后就一直是 `true`。触发条件：`:disabled="submitting"` 从 true 切回 false，或者所在表单解除禁用。之后两侧勾选、搜索、分页和穿梭按钮全部保持禁用。`props.disabled` 本身经 `useFormInject` 合并进了 `formDisabled`（`app/composables/useFieldGroup.ts:373-374`），所以首次禁用能生效，问题只在解除禁用。
  第 1073 行 `isDisabled || isDisabled.value` 里的 `isDisabled` 是形参（`boolean | undefined`），遮蔽了外层的 computed，`.value` 恒为 `undefined`。结果是整体禁用时，左栏和非单向右栏的条目仍然套用 `hover:bg-gray-2` 和手型光标。这两处都是暂存区新加的（HEAD 用的是 `props.disabled`），vue-tsc 会报 TS7022，以及「boolean 上不存在 value」。
- 改法：
  ```ts
  // useFormInject 已合并表单级与自身的 disabled，这里只做布尔收紧
  const isDisabled = computed(() => formDisabled.value === true);

  function getItemClass(isSelected: boolean, itemDisabled: boolean | undefined) {
    return cn(ui.value.item(), isSelected && ui.value.itemSelected(),
      itemDisabled || isDisabled.value ? "opacity-50 cursor-not-allowed" : !isSelected && "hover:bg-gray-2");
  }
  ```
- 影响：不改公开 API，恢复 `disabled` 的文档语义。UniApp 端没有同名组件。回归时要覆盖「禁用 → 解除」和「表单禁用 → 解除」两条路径。

### [中] RebornTable / RebornTimeline：不带 props 的函数式组件包着插槽渲染，父组件重渲染时它不跟着更新
- 位置：`app/components/reborn/ui/reborn-table/RebornTable.vue:48-57`、`:76`；`app/components/reborn/ui/reborn-timeline/RebornTimeline.vue:84-87`、`:132`
- 类别：插槽与透传
- 依据：`references/render-functions.md`「Prefer templates over render functions」；`references/component-fallthrough-attrs.md`「`useAttrs()` is current-but-not-reactive」（插槽同理，生产构建下 `useSlots()` 不是响应式的）
- 现状：
  ```ts
  const RenderTable = () => h(TableView, { ...attrs, ... columns: props.columns ?? collectColumns(slots.default?.(), props.data[0]) },
    Object.fromEntries(Object.entries(slots).filter(([name]) => name !== 'default')));
  // <template><RenderTable /></template>
  ```
  `<RenderTable />` 和 `<SlotItems />` 编译出的 vnode 没有 props，`shouldUpdateComponent` 在 `patchFlag` 为 0 时返回 false，所以父组件因为插槽变化被强制更新时，这两个函数式组件不会重新执行。它们只跟着自己渲染时读到的响应式数据更新，下面两种情况会失效：
  1. 条件具名插槽：`<template v-if="x" #empty>`、`#footer`、`#cell-xxx` 增删后，RebornTable 自己的 `instance.slots` 已经更新，TableView 手里拿的却还是上次 `Object.fromEntries` 的快照，插槽不出现，或者已经删掉的插槽还在渲染。
  2. 插槽闭包捕获了外层 `v-for` 或作用域插槽的变量。比如在父级 `v-for="g in groups"` 里写 `<RebornTimelineItem v-for="e in g.events">`，或者在表格 `#cell-x="{ row }"` 里再嵌一个时间线。数据整批替换后，父级生成了新的插槽闭包，但 SlotItems / RenderTable 只追踪了旧对象上的字段，列表保持旧内容。

  另外 `...attrs` 展开时，如果 attrs 为空，就一次 get 都不会触发，也就建立不了依赖，之后新加的 `style` / `id` 不会透传给 TableView（边界情况）。
- 改法：把插槽求值放回组件自己的模板，让父级的强制更新能传下去。
  - RebornTimeline：`<template v-else><component :is="node" v-for="(node, i) in slotNodes()" :key="node.key ?? i" /></template>`。`slotNodes()` 就是现在 SlotItems 的函数体，`:is` 接收 VNode 时 Vue 会克隆后渲染。
  - RebornTable：直接在模板里渲染 TableView，用动态插槽转发：
    ```vue
    <TableView ref="view" v-bind="$attrs" :table="props" :models="models" :notify="emit"
      :columns="props.columns ?? collectColumns($slots.default?.(), props.data[0])">
      <template v-for="name in forwardedSlotNames" #[name]="scope"><slot :name="name" v-bind="scope ?? {}" /></template>
    </TableView>
    ```
    `forwardedSlotNames` 在模板表达式里由 `Object.keys($slots)` 去掉 `default` 得到。这种写法同样在真实渲染上下文里收集列，原注释说的「条件列与 SSR 首屏可用」照样成立。
- 影响：公开 API 不变。改动后 RebornTable 每次重渲染都会重新收集列（现在 RenderTable 也是在数据变化时重新收集），需要回归声明式列、条件列和具名单元格插槽。UniApp 端没有 table / timeline。

### [中] RebornTable：任何状态变化都整表重建，没有行级跳过
- 位置：`app/components/reborn/ui/reborn-table/TableView.ts:363-401`（renderRow / renderBody）、`:415-425`（renderScrollContent）、`:298-362`（renderCell）
- 类别：性能
- 依据：`references/perf-v-once-v-memo-directives.md`「1000 items, selection changes → 2 items re-render」；`references/perf-virtualize-large-lists.md`
- 现状：整个表体在 `TableScrollContent` 的一次渲染里生成，每个单元格都读 `state.selectedSet`、`isCurrentRow`、`drag.draggingKey`、`cellSpans` 等表级状态：
  ```ts
  const selected = state.selectedSet.value.has(item.key);
  ...state.leaves.value.map((column, index) => renderCell(item, column, index))
  ```
  勾选一行、点当前行、展开、拖拽开始和结束（各一次），都会让 N 行 × M 列全部重新生成 vnode。每格还要跑一次 `cls()`（tv 槽位 + tailwind-merge），以及用户的单元格插槽 / `formatter`。默认 `pagination: false`，表格也没有虚拟滚动，几百行数据时每次勾选都会有明显的重渲染开销（需要用 Performance 面板量化）。
- 改法：按行建立更新边界，二选一：
  1. 抽一个 `TableBodyRow` 组件（每行一个实例，单元格不要再拆组件），props 只传 `item`、`selected`、`current`、`dragging`、`hovered`、本行 `spans`，再加一个汇总表级布局输入的版本号（`leaves`、`fixedOffsets`、`horizontalOverflow`、`loading` 等）。单元格插槽在行组件自己的渲染里调用，用户插槽的依赖也就记在行上。这样勾选只会重渲染一行和表头复选框。
  2. 在 renderBody 里用 `withMemo`（编译后 `v-memo` 用的就是它），按行键缓存行 vnode，依赖数组同上。缺点是用户插槽读取的外部状态不在依赖里，会被跳过，需要在文档里写明。

  文档里补一句「大数据请开启分页」。
- 影响：不改公开 API。改法 1 改的是内部结构，需要回归合并单元格、展开行、拖拽、固定列阴影和悬停。

### [中] RebornTable：每个溢出提示单元格都是一个组件实例，各挂一个 ResizeObserver 和一个 MutationObserver
- 位置：`app/components/reborn/ui/reborn-table/TableOverflowTooltip.ts:49-61`；创建点 `app/components/reborn/ui/reborn-table/TableView.ts:324-335`
- 类别：性能
- 依据：`references/perf-avoid-component-abstraction-in-lists.md`「Each component instance has memory and render overhead - abstractions multiply this in lists」
- 现状：表级 `showOverflowTooltip` 打开后，每个普通单元格都会创建 `TableOverflowTooltip`：
  ```ts
  observer = new ResizeObserver(measure); observer.observe(element.value);
  contentObserver = new MutationObserver(measure); contentObserver.observe(element.value, { childList: true, characterData: true, subtree: true });
  onUpdated(measure);
  ```
  50 行 × 8 列就是 400 个组件实例加 800 个观察器。而且 TableView 用渲染函数传 `{ default: () => content }`，插槽对象不带 `$stable` 标记，所以每次整表重绘（见上一条）都会强制更新所有提示单元格，逐格跑 `onUpdated → measure` 读 `scrollWidth`。浮层实例是按需创建的，这一点做得对，但测量这一层没有共享。
- 改法：TableView 持有一个共享的 ResizeObserver，用 `provide` 下发 `observe(el, cb)` / `unobserve(el)`，单元格只注册回调。MutationObserver 去掉，内容变化交给共享 RO 加首次交互时的 `measure()`（`open()` 里已经有了）。`onUpdated(measure)` 只在 `activated` 为真时执行。
- 影响：不改公开 API。需要回归键盘聚焦，因为 `tabindex` 依赖溢出测量结果。

### [中] RebornTable：立即执行的 watcher 在 setup 阶段裁剪 `selectedKeys`，数据异步到达时预选会被清空（待确认是否属于预期）
- 位置：`app/components/reborn/ui/reborn-table/table.state.ts:46-58`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Emit events instead of mutating parent state directly」：模型写回应当由用户操作触发，不应在初始化阶段静默改写父级值
- 现状：
  ```ts
  watch([sourceRows, () => selectionColumn.value?.reserveSelection], ([rows, reserve]) => { ...
    if (!reserve) { const keys = models.selectedKeys.value.filter(key => next.has(key));
      if (keys.length !== models.selectedKeys.value.length) models.selectedKeys.value = keys; }
  }, { immediate: true });
  ```
  常见的编辑页写法：父级先拿到已选 ID 写进 `v-model:selected-keys`，`data` 稍后才加载回来。setup 时 `data` 还是 `[]`，立即执行的回调会把所有键裁掉，并 `emit('update:selectedKeys', [])`，父级的预选就丢了。文档写的是「`reserveSelection` 数据更新时保留选中键，默认不开启」，没有说明首屏空数据时也会裁剪。

- 影响：改法 (1) 会改变运行时行为，需要同步 `content/2.components/data/reborn-table.md` 的 `reserveSelection` 说明和知识库。UniApp 端没有表格。

### [中] RebornTabs / RebornTimeline：子组件在 setup 里向父级登记，SSR 首屏的头部为空、列轨道不对
- 位置：`app/components/reborn/ui/reborn-tabs/RebornTabs.vue:112`、`:352-355`、`:764`；`app/components/reborn/ui/reborn-tabs/RebornTabPane.vue:66`；`app/components/reborn/ui/reborn-timeline/RebornTimeline.vue:36-60`、`:91-95`；`app/components/reborn/ui/reborn-timeline/RebornTimelineItem.vue:40-41`
- 类别：SSR
- 依据：`references/component-data-flow.md`「Provide/Inject：Place the provider at the nearest common ancestor」。登记表本身没问题，问题出在父级渲染时依赖登记结果
- 现状：SSR 是单遍渲染。RebornTabs 渲染头部 `v-for="pane in panes"` 时 `panes` 还是 `[]`，TabPane 要等默认插槽渲染时才执行 setup 并调用 `ctx.addPane(meta)`，头部字符串早已写出。所以服务端 HTML 里只有当前面板内容，没有任何 `role="tab"` 按钮。水合时客户端同样先渲染空头部（因此不报 mismatch），挂载后才补出头部，造成布局跳动；不跑 JS 的环境（爬虫、读屏预览）也看不到标签。RebornTimeline 同理：`columns` 依赖 `itemSides`，子项在 setup 里 `reportSide`，所以只要有节点用了 `labelPosition="left"`，SSR 输出的根节点列轨道就是 `end`，水合后才改成 `start` / `both`。items 模式下父组件明明拿得到 `props.items[*].labelPosition`，也照样走了登记。
- 改法：父级在自己渲染时直接从插槽 vnode 读出头部元信息，登记只用来拿 DOM 引用：
  - RebornTabs：参照 `table.columns.ts` 的 `collectColumns`，在渲染阶段展开 `slots.default?.()`，筛出 `RebornTabPane` 的 vnode，读取 `key` / `title` / `disabled` / `closable` 和 `children.title` 来生成头部。`addPane` 只保留 `el` 和排序用途。
  - RebornTimeline：items 模式直接用 `props.items` 算 `columns`。插槽模式用渲染阶段已经展开的 vnode，读 `node.props?.labelPosition ?? node.props?.['label-position']`。
- 影响：公开 API 不变。验证方法：直接 SSR 一个不包 `ClientOnly` 的页面（文档站的 ComponentViewer 走 ClientOnly，现有页面暴露不出这个问题），curl 拿到 HTML 后检查 `role="tab"` 是否存在。UniApp 端没有 SSR，不需要同步，但 `reborn-tabs` 两端的登记机制会因此不同构，需要在实现注释里写明。

### [中] RebornTabs：指示条、底板和内容高度动画逐帧写响应式样式，整个组件逐帧重渲染
- 位置：`app/components/reborn/ui/reborn-tabs/RebornTabs.vue:419-432`（indicatorStyle）、`:475-491`、`:498`（useLiquidSlider 的 style）、`:657-661`（stageHeight）、`:784`、`:791`、`:840`；每次渲染都要重算的 `:299-321`（`ui` 返回函数）和 `:330-338`（`tabClass`）
- 类别：性能
- 依据：`references/animation-state-driven-technique.md`（状态驱动动画适用于低频状态，逐帧插值交给动画库直接写 DOM）；`references/reactivity.md`「Use computed for reusable class/style logic」
- 现状：spring 动画的每一帧 `onUpdate` 都会 `indicatorStyle.value = {...}` 赋一个新对象，内容高度动画每帧也要写一次 `stageHeight.value`。这两个值都在 RebornTabs 的模板里读取，所以默认的 `type="line"` 每切一次标签，动画期间整个 RebornTabs 模板会每帧重跑一遍：N 次 `tabClass()`（每次 `theme({...}).tab()` 都会走一遍 tv 和 tailwind-merge）、十几个 `ui.xxx()` 槽位函数，还有默认插槽的重新执行。`ui` 计算属性缓存的是函数而不是字符串，每次渲染都要重新求值一遍。

  2. 如果要保留响应式写法，就把指示条、底板拆成只接收 `style` 的极小子组件，逐帧只重渲染这一层。
  3. 把 `ui` 改成直接缓存字符串（`ui.value.nav`），`tabClass` 改成按 pane 计算的数组 computed。
- 影响：内部实现，不改 API。UniApp 端 `reborn-tabs` 的动画实现另审（U 分片）。

### [中] RebornTextarea：没有用 `defineModel`，手写的同步 watcher 忽略 `undefined`，遇到 `null` 会让渲染报错
- 位置：`app/components/reborn/ui/reborn-textarea/RebornTextarea.vue:15`、`:49-58`、`:71`、`:117-127`、`:152-155`
- 类别：数据流
- 依据：项目规则「双向绑定用 `defineModel`」；`references/component-data-flow.md`「Use `defineModel` for v-model in Vue 3.4+」
- 现状：
  ```ts
  const value = ref(props.modelValue ?? "");
  watch(() => props.modelValue, (val) => { if (val !== undefined) value.value = val; ... });
  // 模板 :length="value.length" / {{ value.length }}
  ```
  两种情况会出错：(1) 父级把值重置为 `undefined`（例如 `form.remark = undefined`）时本地副本不清空，输入框和字数统计都停留在旧文本；(2) 重置或后端回填为 `null` 时 `value.value = null`，开着 `showWordLimit` 就会在渲染中抛出「Cannot read properties of null (reading 'length')」。初值用了 `?? ""`，后续同步却没有用，两处不一致。
- 改法：
  ```ts
  const model = defineModel<string | null>({ default: "" });
  const text = computed(() => model.value ?? "");
  function handleInput(e: Event) {
    const next = (e.target as HTMLTextAreaElement).value;
    model.value = next;
    emit("change", next); // 受控模式下同步读 model 仍是旧值，载荷用本地 next
    validate("change");
    if (props.autoHeight) adjustHeight(e.target as HTMLTextAreaElement);
  }
  watch(model, () => { if (props.autoHeight && textareaRef.value) nextTick(() => adjustHeight(textareaRef.value!)); });
  ```
  同时从 `defineEmits` 里去掉 `update:modelValue`，模板改读 `text`。
- 影响：对外的 `modelValue` / `update:modelValue` 不变。UniApp 端 `reborn-textarea` 也是同样的手写同步（`packages/uniapp-project/src/components/reborn-textarea/RebornTextarea.vue:125`），建议 U 分片一并处理，保持两端一致。

### [中] RebornTimePanel：每次状态变化都重渲染全部选项，每项要做两次 tv 合并；毫秒格式下有 3000～6000 个节点
- 位置：`app/components/reborn/ui/reborn-time-picker/RebornTimePanel.vue:144-155`（options 三倍展开）、`:180-223`（`ui` 返回函数）、`:618-639`（选项渲染）
- 类别：性能
- 依据：`references/perf-v-once-v-memo-directives.md`「v-memo: Conditional Memoization for Lists」；`references/perf-virtualize-large-lists.md`
- 现状：每列都渲染三份选项（时 72、分 180、秒 180、毫秒 3000），范围模式再乘以 2。每个选项的 class 是这样算的：
  ```vue
  :class="ui.item({ class: isDisabledValue(...) ? ui.itemDisabled() : getState(role)[unit] === option.value ? ui.itemActive() : ui.itemIdle() })"
  ```
  每项要调两次 tv 槽位函数加 `cn`。任何一次点击、键盘操作或滚动停下后的落位，都会让整个面板所有列重新渲染：`HH:mm:ss` 单值大约 860 次 tv/cn，范围模式翻倍，带 `SSS` 时超过 6000 次，另有 3000 以上的 DOM 节点。而且面板在每次展开时都会重新挂载（RebornTransition 默认 `destroy`）。
- 改法：
  1. 预先算好三种状态的类名：`const itemClasses = computed(() => ({ active: ui.value.item({ class: ui.value.itemActive() }), idle: ..., disabled: ... }))`，渲染时直接按状态取。
  2. 选项节点加 `v-memo="[getState(role)[unit] === option.value, isDisabledValue(role, unit, option.value), disabled, itemClasses]"`，选中项变化时只更新新旧两项。
  3. 毫秒列按可视窗口渲染（只渲染选中值前后若干项，再用占位撑出滚动高度），或者在文档里注明毫秒列的成本。

- 现状：`mountContainer()` 在没有 `document` 时直接返回，但 `open()` 照样执行 `addMessage()`：消息被推进跨请求共享的 `messageState.list`，服务端 `setTimeout` 照常运行，`onClose` 在服务端回调。`duration: 0` 的消息还会永久留在单例里。`useAsyncData` 的错误处理等服务端代码路径里调用 `message.error()` 就会触发。
- 改法：`open()` 开头判断 `import.meta.server`（或 `typeof document === "undefined"`），成立就直接 `return Promise.resolve()`。`messageState` 改为只读导出，修改只走 `addMessage` / `closeMessage`。
- 影响：不改 API，服务端调用变成空操作，需要在文档里说明。

### [低] RebornToast：`themeOf(item)` 每条消息每次渲染要调用 5 次
- 位置：`app/components/reborn/ui/reborn-toast/RebornToast.vue:54`、`:112`、`:119`、`:123`、`:129`、`:132`、`:140`、`:150`
- 类别：性能
- 依据：`references/reactivity.md`「Use computed for reusable class/style logic」
- 现状：每次调用都新执行一遍 `messageTheme({ variant, color })`，再各自调用槽位函数。容器每次重渲染都会对所有消息重复做这些计算。
- 改法：用 computed 生成视图模型列表，例如 `stacks` 里每条消息带上 `{ item, cls: { root, iconWrapper, icon, content, close, badge } }`，模板直接取字符串。
- 影响：内部实现。

### [低] RebornTransfer：头部下拉的选项在每次勾选时整批重建
- 位置：`app/components/reborn/ui/reborn-transfer/RebornTransfer.vue:1110-1120`、`:1207-1212`
- 类别：性能
- 依据：`references/reactivity.md`「Prefer computed … keep derivations minimal」
- 现状：`panelMenus` 依赖 `panels`，而 `panels` 依赖勾选集合，所以每勾选一次，`getMenuOptions` 都要对两侧全部搜索结果重新 `map` 出 `SelectOption`（上千条数据时就是上千个新对象），并把新数组交给 RebornSelect。注释写的是「与滚动状态无关，单独缓存」，但它仍然跟着勾选状态一起失效。
- 改法：选项只依赖 `filtered` 和禁用状态，单独做一个 computed；选中值单独做一个 computed。
- 影响：内部实现。

### [低] 写法统一：基础类型用 `ref` 而不是 `shallowRef`，模板引用没有用 `useTemplateRef`，`:style` 用了连字符键，`dayjs.extend` 在每个实例的 setup 里重复执行
- 位置：
  - 基础类型 / 只做整体替换的值用了 `ref`：`reborn-table/TableFilter.ts:18`；`reborn-table/TableOverflowTooltip.ts:23-26`；`reborn-table/table.lazy.ts:17`；`reborn-tabs/RebornTabPane.vue:73`、`:85`；`reborn-text/RebornText.vue:161-176`；`reborn-textarea/RebornTextarea.vue:71-72`；`reborn-time-picker/RebornTimePicker.vue:161`、`:169-170`；`reborn-time-picker/RebornTimePanel.vue:133-134`（只整体替换的对象）；`reborn-tooltip/RebornTooltip.vue:137`、`:147`、`:209`；`reborn-transfer/RebornTransfer.vue:435`、`:472-473`、`:542-543`；`reborn-transition/RebornTransition.vue:264`
  - 模板引用用 `ref(null)`：`reborn-text/RebornText.vue:157`、`:159`、`:168`；`reborn-textarea/RebornTextarea.vue:73`；`reborn-time-picker/RebornTimePicker.vue:167-168`；`reborn-tooltip/RebornTooltip.vue:139-145`；`reborn-transition/RebornTransition.vue:265`；`reborn-table/TableOverflowTooltip.ts:20-21`（渲染函数里的引用不适用 `useTemplateRef`，可改为 `shallowRef`）
  - `:style` 连字符键：`reborn-text/RebornText.vue:87-92`（`"-webkit-line-clamp"`、`"word-break"` 等）
  - `dayjs.extend(customParseFormat)` 写在 setup 里：`reborn-time-picker/RebornTimePanel.vue:53`、`reborn-time-picker/RebornTimePicker.vue:65`（`time-picker.utils.ts:5` 已经在模块级注册过）
- 类别：其他
- 依据：`references/reactivity.md`「Always use `shallowRef()` instead of `ref()` for primitive values」；`references/sfc.md`「Access DOM / component refs with `useTemplateRef()`」「Use camelCase in `:style` bindings」
- 现状：功能上没有问题，只是与技能推荐的写法和仓库里其他组件不一致；`dayjs.extend` 每创建一个实例就执行一次（dayjs 内部会去重，没有副作用）。
- 改法：基础类型和只做整体替换的对象改用 `shallowRef`；SFC 里的模板引用改用 `useTemplateRef`；样式键改成 `WebkitLineClamp`、`wordBreak` 这类驼峰写法；删掉两处组件内的 `dayjs.extend`，只保留 `time-picker.utils.ts` 的模块级注册。
- 影响：纯写法调整。建议在相关组件有其他改动时顺带处理，不必单独发一个 PR。
