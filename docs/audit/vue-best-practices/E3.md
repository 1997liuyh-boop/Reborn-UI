### [高] RebornFormDemo：`reactive({ ...initialForm })` 只做浅拷贝，联系人数组与模块级常量共用，离开页面再回来时上次添加的联系人还在，重置也清不掉
- 位置：
  - `app/components/reborn/examples/reborn-form/RebornFormDemo.vue:127`（`const form = reactive<FormData>({ ...initialForm })`）
  - `app/components/reborn/examples/reborn-form/RebornFormDemo.vue:143-150`（`addContact` 往 `form.contacts` 里 `push`）
  - `app/components/reborn/examples/reborn-form/RebornFormDemo.vue:279-288`（`v-model="contact.name"` 等直接改数组元素）
  - `app/components/reborn/examples/reborn-form/reborn-form-demo.config.ts:49-64`（模块级 `initialForm`，含 `contacts: []`、`interest: []`、`dateRange: []`）
  - 关联：`app/components/reborn/ui/reborn-form/RebornForm.vue:182-195`（挂载时把当前 `modelValue` 深拷贝成重置快照）
- 类别：响应性 / 数据流
- 依据：`references/reactivity.md`「选对声明方式：对象 / 数组状态由组件实例自己持有」；`references/composables.md`「Create shared state once per intended scope」。这里的状态本应每个实例一份，却意外跨实例共享了。
- 现状：
  ```ts
  const form = reactive<FormData>({ ...initialForm });
  function addContact() {
    form.contacts.push({ phone: "", email: "", name: "", no: form.contacts.length + 1 });
  }
  ```
  展开运算只复制第一层，`form.contacts` 与 `initialForm.contacts` 是同一个原始数组，`push` 和对 `contact.xxx` 的修改都写进了模块级常量。ES 模块只求值一次，触发条件是：
  1. 在「联系人列表」点几次「添加联系人」并填写；
  2. 从侧栏切到别的组件文档，再切回表单文档（客户端路由，模块不重新求值）；
  3. 新挂载的 demo 一上来就带着上次的联系人；`RebornForm` 在 `onMounted` 里把这份已被污染的数据拍成重置快照，点「重置」也恢复不到空列表。

  `interest`（`RebornCheckboxGroup` 每次整体替换数组）和 `dateRange`（日期选择器整体赋值）目前碰巧不受影响，但只要换成原地修改的控件就会同样泄漏。使用者把这段照抄到「弹窗里的编辑表单」（`v-if` / `destroy-on-close` 反复挂载）时，第二次打开就会看到上一次的残留数据，这是这个写法最常见的事故形态。
- 改法：初始值改成工厂函数，每次挂载拿一份新对象：
  ```ts
  // reborn-form-demo.config.ts
  /** 每次调用返回一份新的初始表单，避免多个实例共用同一组数组 */
  export function createInitialForm(): FormData {
    return { username: '乐一番', gender: 1, /* …其余原始值… */ dateRange: [], interest: [], contacts: [], isAgree: false }
  }
  // RebornFormDemo.vue
  const form = reactive<FormData>(createInitialForm());
  ```
  或者至少用 `structuredClone(initialForm)`。
- 影响：只动 demo 与 demo 配置，不涉及组件公开 API。`RebornFormDemo.vue` 是知识库 examples 的来源，改后需 `pnpm kb:build --only reborn-form`。UniApp 端演示页属 P1 分片，建议一并检查是否有同样的浅拷贝。

### [中] RebornDialogDemo：在 setup 里用 `useOverlay().create()` 建了 11 个服务式实例，从不注销；每次进入页面都往模块级 Map 里追加，打开中的弹窗在路由切换后也不会被收掉
- 位置：
  - `app/components/reborn/examples/reborn-dialog/RebornDialogDemo.vue:214-281`（11 处 `overlay.create(...)`）
  - `app/components/reborn/examples/reborn-dialog/RebornDialogDemo.vue:284-344`（各 `open*Dialog`）
  - 关联：`app/composables/useOverlay.ts:68`（模块级 `overlayStates`）、`:172-203`（`create` 只写入不清理）、`:311-334`（`unmount` 需要手动调用）
- 类别：生命周期与清理
- 依据：`references/composables.md`「Keep related state, actions, and lifecycle cleanup together」；SKILL.md 自检项「side effects clean up with their owner」。
- 现状：
  ```ts
  const overlay = useOverlay();
  const playgroundDialog = overlay.create(RebornDialog, { props: state.value });
  // …共 11 个 create，组件内没有任何 onBeforeUnmount / unmount 调用
  ```
  `useOverlay` 不绑定调用方生命周期，`create` 写进模块级 `overlayStates`，只有显式 `unmount(id)` 或 `destroyOnClose` 才删除。于是：
  1. 每次进入 Dialog 文档页都会新增 11 条记录，`playgroundDialog` 那条还持有 demo 的 `state` 响应式对象，页面来回切换时只增不减；
  2. 打开任一服务式弹窗（它用独立的 `createApp` 挂在 `body` 上）后按浏览器后退，新页面上仍然盖着这个弹窗，直到手动关闭。
- 改法：demo 侧在卸载时统一注销，并示范这个收尾动作：
  ```ts
  const instances = [playgroundDialog, editProfileDialog, nestedDialog, /* … */ customIconDialog];
  /** 页面卸载时注销全部服务式实例，避免模块级登记表累积、弹窗残留到下一个页面 */
  onBeforeUnmount(() => instances.forEach(item => overlay.unmount(item.id)));
  ```
  根因在组合式函数：更合理的是 `useOverlay` 在有组件实例时用 `onScopeDispose` 自动注销本作用域创建的实例。这一点属于 C1 分片，此处只记录 demo 侧的表现。
- 影响：demo 侧改法不涉及公开 API。若在 `useOverlay` 里加自动注销，会改变「跨组件持有实例」的既有行为，需要回归 Drawer demo 与所有服务式调用，并同步文档「注意事项」。

- 位置：

  - `app/components/reborn/examples/reborn-dialog/dialogs/CloudSyncDialog.vue:20-33`、`:47-48`（`saving` 只在确认时置 true，取消按钮随之隐藏）
  - 关联：`app/composables/useOverlay.ts:27-34`、`:134-152`（`onConfirm` 选项：自动 loading、进行中拦截关闭、成功后关闭）
- 类别：生命周期与清理 / 数据流
- 依据：`references/reactivity.md`「Clean up async effects」：异步回调落地时，要确认它针对的还是当初那次操作。
- 现状：
  ```ts
  const result = await cloudSyncDialog.open();
  if (result === "confirm") {
    await new Promise((resolve) => setTimeout(resolve, 2000));
    cloudSyncDialog.close("synced");
  }
  ```
  `open()` 在点确认时就已 resolve，弹窗并没有进入受保护状态：取消按钮虽被隐藏，ESC 和点遮罩仍会走 `onUpdate:open → close(id)`。触发条件：点「立即同步」→ 2 秒内按 ESC → 再点「执行同步（服务式）」重新打开 → 第一次的定时器到点调用 `close("synced")`，把刚打开的新弹窗关掉，并让第二次 `open()` 以 `"synced"` 结束。
- 改法：用组合式函数已有的 `onConfirm`，它会注入 loading、在进行中拦截关闭，成功后自动关闭：
  ```ts
  const cloudSyncDialog = overlay.create(CloudSyncDialog, {
    props: {},
    /** 确认后模拟 2 秒同步；期间确认按钮 loading，ESC / 遮罩不会中途关闭 */
    onConfirm: () => new Promise<void>(resolve => setTimeout(resolve, 2000)),
  });
  ```
  `CloudSyncDialog` 内部自管的 `saving` 与 `defineExpose({ resetState, saving })` 随之可以删掉（见「低」中的封装组件一条）。
- 影响：只改 demo；`onConfirm` 是 `useOverlay` 已有选项。文档「异步确认」一节如引用了 demo 写法需同步。

- 类别：模板 / 数据流
- 依据：`references/sfc.md`「Always provide a stable `:key`」。
- 现状：
  ```vue
  <div v-for="(contact, index) in form.contacts" :key="index">
    <RebornButton @click="form.contacts.splice(index, 1)">…</RebornButton>

  ```
  触发条件：添加 2 个联系人 → 点「提交表单」让第 1 行姓名报错 → 删除第 1 行。错误表以 `contacts-0-name` 为键，原第 2 行下移成下标 0 后直接显示「Name 最少两个字符」，尽管它的姓名是合法的；关闭实时校验（`trigger: 'none'`）时这个错误会一直挂到下次提交。另外，下标作 key 让 Vue 复用的是「位置」而不是「这一条联系人」：真正被卸载的是最后一行的组件实例，各输入控件内部的临时状态（输入中的草稿、焦点、错误提示的过渡）会跟着位置错到别的联系人上。

  1. 联系人带稳定 id，用 id 作 key：

     let contactSeed = 0;

  ```vue
  <div v-for="(item, i) in serviceLogs" :key="item.time + item.msg + i">
  ```

  ```ts
  let logSeed = 0;
  function pushLog(msg: string, tone: "info" | "success" = "info") {
    serviceLogs.value.push({ id: ++logSeed, time: new Date().toLocaleTimeString("zh-CN", { hour12: false }), msg, tone });
    if (serviceLogs.value.length > 7) serviceLogs.value.shift();
  }
  ```
  模板改为 `:key="item.id"`。
- 影响：只改 demo，不涉及组件 API。
