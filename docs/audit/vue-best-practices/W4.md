### [高] RebornLayoutAside：breakpoint 在 setup 阶段同步读取 matchMedia，窄屏首屏水合后侧栏停在展开态

- 位置：`app/components/reborn/ui/reborn-layout/RebornLayoutAside.vue:163-181`（`watch(..., { immediate: true })`）；受影响的绑定：`:147-151`（rootStyle）、`:121-123`（arrowIcon）、`:192`（`data-collapsed`）
- 类别：SSR
- 依据：`vue-debug-guides/reference/ssr-hydration-mismatch-causes.md`「服务端与客户端首帧输出必须一致」；`vue-debug-guides/reference/ssr-platform-specific-apis.md`「浏览器 API 放到 onMounted」
- 现状：
  ```ts
  watch(() => props.breakpoint, (breakpoint) => {
    teardownBreakpoint();
    if (!breakpoint || typeof window === "undefined") return;
    mediaQuery = window.matchMedia(`(max-width: ${layoutSiderBreakpoints[breakpoint] - 0.02}px)`);
    // ...
    if (mediaQuery.matches) { emit("breakpoint", true); setCollapsed(true, "responsive"); }
  ```
  服务端没有 `window`，输出展开态（`--reborn-layout-aside-width: 200px`、`data-collapsed="false"`、向左箭头）。客户端水合时 immediate 回调在 setup 里同步执行，视口低于断点就把 `isCollapsed` 置为 true，首帧 vnode 变成收起态。Vue 水合只补事件监听等少数属性，不修正 style / class / data-*（已对照 `node_modules/@vue/runtime-core/dist/runtime-core.cjs.prod.js:1630-1638` 的 hydrateElement 确认），所以 DOM 保持服务端的展开宽度。之后 vnode 已经是收起值，只要状态不再变化，DOM 就不会被纠正。
  触发条件：Nuxt SSR + 设置 `breakpoint` + 首屏视口窄于断点（典型场景是手机打开后台布局，正是这个属性的主要用途）。表现：侧栏显示为展开宽度、箭头方向错误，首次点击触发器看起来没反应（vnode 从收起切到展开，而 DOM 本来就是展开宽度）。开发环境会打印 hydration style / class mismatch。
- 改法：首次判定挪到挂载之后，watch 只负责断点切换：
  ```ts
  const isMounted = shallowRef(false);
  onMounted(() => { isMounted.value = true; });
  watch([() => props.breakpoint, isMounted], ([breakpoint, mounted]) => {
    teardownBreakpoint();
    // 挂载前不读视口，保证水合首帧与服务端一致
    if (!breakpoint || !mounted) return;
    mediaQuery = window.matchMedia(`(max-width: ${layoutSiderBreakpoints[breakpoint] - 0.02}px)`);
    // 其余逻辑不变
  });
  ```
  也可以直接用 VueUse 的 `useMediaQuery`，它在挂载前恒为 false，与服务端一致。挂载后才收起会有一次展开→收起的宽度过渡，这正是 `hasSider` 注释里预期的 SSR 行为；需要首帧就收起的使用方可以传 `default-collapsed` 或受控 `collapsed`。
- 影响：不改公开 API；`breakpoint` / `collapse` 事件从 setup 阶段推迟到挂载后触发。文档「breakpoint 挂载时只会收起」（content/2.components/layout/reborn-layout.md:331）语义不变，可补一句「挂载后判定」。UniApp 端没有这个组件。回归点：受控 `v-model:collapsed` 初值的同步时机。

- 位置：
  - `app/components/reborn/ui/reborn-dialog/RebornDialog.vue:136-139`（关闭继承），模板 `:813-881` 全文没有 `$attrs`
  - `app/components/reborn/ui/reborn-input/RebornInput.vue:289-292`（inputAttrs 剔除了 style）、`:510`（根节点没有绑定 style）
  - `app/components/reborn/ui/reborn-input-number/RebornInputNumber.vue:217-220`、`:470`（同上）
  - `app/components/reborn/ui/reborn-input-otp/RebornInputOtp.vue:10`（关闭继承），模板 `:125-129` 没有 `$attrs`
  - `app/components/reborn/ui/reborn-fireworks/RebornFireworks.vue:313-318`（多根节点，只手动转发 `$attrs.class`）
- 类别：插槽与透传

- 现状：Dialog / InputOtp 关闭自动继承后，没有任何节点接收 `$attrs`，`id`、`style`、`data-*`、`aria-*`、未声明事件的监听器全部丢失。Input / InputNumber 的 `class` 走 prop、其余属性交给原生 input，唯独 `style` 被解构出来以后没人使用：
  ```ts
  const inputAttrs = computed(() => {
    const { class: _class, style: _style, ...rest } = attrs;
    return rest;
  });
  ```
  所以 `<RebornInput style="width: 240px">` 不生效。Fireworks 因为模板访问了 `$attrs.class`，Vue 不再发出多根透传警告，其余属性悄无声息地丢掉。Drawer（`RebornDrawer.vue:366` 把 attrs 绑在 section 上）和 Header（`RebornHeader.vue:158`）是正确的写法。
- 改法：

  - Input / InputNumber：根节点加 `:style="attrs.style"`（InputNumber 的根节点就是 wrapper）。

  - Fireworks：`defineOptions({ inheritAttrs: false })`，在容器 div 上 `v-bind="$attrs"`，去掉手写的 `:class="$attrs.class"`。
- 影响：不改 props / emits；原先被忽略的属性会开始生效，如果使用方以前误传过监听器，这些监听器会开始触发。UniApp 端走 customStyle / customClass，不受影响。文档可在 API 一节补一句「其余属性透传到 xx 节点」。

### [中] RebornDialog：根节点无条件拦截滚轮，面板里自带滚动的子元素滚不动

- 位置：`app/components/reborn/ui/reborn-dialog/RebornDialog.vue:821`
- 类别：模板
- 依据：`references/sfc.md`「模板保持声明式，逻辑放 script」；滚轮事件冒泡到祖先后被 preventDefault，浏览器就会取消这次默认滚动
- 现状：
  ```vue
  @wheel="(e) => !props.scrollable && !penetrable && e.preventDefault()"
  ```
  `scrollable` 为 false（默认）时，面板里任何后代的滚轮事件都会冒泡到根节点被取消：带 max-height 的表格、RebornScrollbar（原生滚动，`scrollbar/RebornScrollbar.vue:512`）、内容超出 rows 的 textarea、关闭 portal 的下拉列表，都没法用滚轮滚动。文档（content/2.components/miscellaneous/reborn-dialog.md:338）只提醒「长内容要开 scrollable」，没说子元素自身的滚动也会被吞掉。
- 改法：只在事件路径上没有可滚动元素时才拦截，并把处理函数移到 script：
  ```ts
  function onRootWheel(event: WheelEvent) {
    if (props.scrollable || penetrable.value) return;
    // 面板内有能继续滚动的元素时放行，交给它自己滚
    for (let el = event.target as HTMLElement | null; el && el !== event.currentTarget; el = el.parentElement) {
      const { overflowY } = getComputedStyle(el);
      if (/(auto|scroll)/.test(overflowY) && el.scrollHeight > el.clientHeight) return;
    }
    event.preventDefault();
  }
  ```
- 影响：不改 API；要同步改文档的注意事项和 `scrollable` 一行的描述。回归：未开 scrollable 时背景页面仍不可滚；lockScroll 关闭的场景要验证子元素滚到底后滚动会不会传到 body，必要时给根节点加 `overscroll-contain`。

### [中] RebornDraggable：本地副本 list 与 modelValue 脱节，拖到项外松手后显示顺序与数据不一致

- 位置：`app/components/reborn/ui/reborn-draggable/RebornDraggable.vue:9`、`:18-22`、`:46-57`、`:59-62`、`:64-79`、`:111`
- 类别：数据流
- 依据：`references/component-data-flow.md`「Props down / Events up」；`SKILL.md`「Keep state predictable: one source of truth」
- 现状：dragenter 时直接重排本地 `list`，只在 `drop` 时 emit；而 `drop` 只能落在项上（`@dragover.prevent` 只挂在项元素上）。
  ```ts
  const onDrop = () => { emit('update:modelValue', list.value); emit('change', list.value); };
  const onDragEnd = () => { /* …… */ dragIndex.value = -1; isDragging.value = false; emit('end'); };
  ```
  触发条件：拖动经过其他项后在 gap-4 间隙或列表外松手，或者按 Esc 取消拖拽。这时只有 dragend、没有 drop：页面已经显示新顺序，modelValue 还是旧顺序；只要父组件之后不改 modelValue，两者就一直对不上。父组件拒绝这次排序（单向 `:model-value` 加异步确认失败）时同样不会回滚：拖拽期间 watch 被 `isDragging` 跳过，之后 props 又没变。
- 改法：以 modelValue 为准，拖拽结束时统一回读：
  ```ts
  let dropped = false;
  const onDrop = () => { dropped = true; emit('update:modelValue', list.value); emit('change', list.value); };
  const onDragEnd = () => {
    // ……原有收尾逻辑
    if (!dropped) list.value = [...props.modelValue];            // 取消或落在项外：回滚
    else nextTick(() => { list.value = [...props.modelValue]; }); // 以父组件接受的结果为准
    dropped = false;
  };
  ```
  顺带按项目规则改用 `defineModel`（见低级「项目规则」一条）。
- 影响：不改 API；文档补一句「没在项上松手视为取消」。UniApp 端是独立的触摸实现，需要在 U 分片核对有没有同类的状态分叉。

- 依据：`references/component-data-flow.md`「Use defineModel for v-model」；`references/reactivity.md`「保持单一数据源」

  ```ts

  watch(() => props.modelValue, (val) => { if (isActive.value !== val) isActive.value = val; });

- 影响：`update:modelValue` 改为立即触发，属于行为变更，需要改文档 :136、:140、:142、:180；与 UniApp 端时序对齐，两端一致性更好。

  // ……

  ```
