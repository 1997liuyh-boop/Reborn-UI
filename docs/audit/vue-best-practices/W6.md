### [高] RebornSplitter / RebornSplitterPanel：面板挂载后才按先后顺序登记下标，SSR 首屏没有尺寸，动态增删面板后尺寸、拖拽条、折叠状态全部错位
- 位置：
  - `app/components/reborn/ui/reborn-splitter/RebornSplitterPanel.vue:41-57`（`onMounted` 登记、`onUnmounted` 注销）
  - `app/components/reborn/ui/reborn-splitter/RebornSplitterPanel.vue:74-88`（`panelStyle` / `showBar` 依赖 `index`）
  - `app/components/reborn/ui/reborn-splitter/RebornSplitter.vue:61-106`（`registerPanel` / `unregisterPanel`）
- 类别：SSR / 组件边界 / 响应性
- 依据：
  - `references/component-data-flow.md`「Provide/Inject：状态由 provider 按实例持有，consumer 不自建副本」。
  - `references/reactivity.md`：派生值要从唯一数据源推导，不要缓存快照。
  - 仓库先例 `reborn-steps.context.ts:30-55`：「每次渲染直接提供位置，不依赖挂载登记；服务端首屏和客户端重排使用同一索引」。
- 现状：
  ```ts
  // RebornSplitterPanel.vue:43
  onMounted(() => { index.value = registerPanel({ size: props.size, min: props.min, max: props.max, resizable: props.resizable, collapsible: props.collapsible }) })
  // RebornSplitter.vue:68-97
  const index = panels.value.length
  panels.value.push(config)
  panelSizes.value = calculateSizes()
  ```
  1. **SSR 首屏**：下标要到 `onMounted` 才有。服务端渲染和水合首帧里 `index` 都是 -1，所以 `panelStyle` 返回 `{}`、`showBar` 为 false。结果是服务端 HTML 里面板按内容宽度排列、没有拖拽条，挂载后才跳到设定比例。每个 SSR 页面首屏都会出现这次布局跳动。
  2. **下标不等于 DOM 顺序**：下标取的是登记先后。用 `v-if` 插到中间的面板挂载得晚，拿到的却是末尾下标，尺寸、拖拽条和 `handleDragStart(index + 1)` 都对错了对象。
  3. **注销后其他面板下标失效**：注销时只 `splice` 了 `panels` 和 `panelSizes`，其余面板缓存的 `index.value` 没跟着更新，`collapsedStates` / `originalSizes` 也没删。删掉一个中间面板后，后面的面板整体错一位；最后一个面板的 `panelSizes[index]` 越界成 `undefined`，失去 flex 样式。剩余尺寸也不会重新分配，总和不再是 100%。
  4. **增删面板会重置拖拽结果**：每次登记都调用 `calculateSizes()` 按配置重算全部尺寸，用户已经拖好的比例被清掉。
  5. **配置变化不生效**：登记的是 props 快照。之后改 `min` / `max` / `resizable` / `collapsible` 都不会生效，只有 `size` 有 watch。
- 改法：
  - 照 `RebornSteps` 的做法改：`RebornSplitter` 在渲染期遍历默认插槽，用一个无 DOM 的 Scope 组件给每个面板 `provide` 位置（index / count），服务端和客户端用同一个索引。
  - 尺寸按面板的稳定 id（`useId()`）存进对象。初始尺寸在渲染期由各面板配置推导出来（computed），不依赖 `onMounted`。
  - 面板配置用 getter 登记（`() => props.min` 等），保持响应。
  - 增删面板时，只把空出来的份额补给相邻面板，不要整体重算。
- 影响：
  - 不改公开 props / emits / slots。
  - Splitter 没有 UniApp 同名组件。
  - 要回归拖拽、`lazy` 幽灵条、折叠 / 展开、`v-model:size`。
  - 修好后可以在文档里补一句「支持动态增删面板」。

### [高] RebornSelect：已选项只从当前 options 里反查，远程搜索替换 options 后触发器上的已选文本 / 标签消失
- 位置：
  - `app/components/reborn/ui/reborn-select/RebornSelect.vue:258-264`（`selectedOptions`）
  - `app/components/reborn/ui/reborn-select/RebornSelect.vue:462`（`displayText`）
  - `app/components/reborn/ui/reborn-select/RebornSelect.vue:465-468`（`visibleTags`）
- 类别：数据流
- 依据：`references/reactivity.md`「保持唯一数据源，其余派生」。这里派生值依赖的数据源（当前 options）并不完整：已选值的展示信息不在里面。
- 现状：
  ```ts
  const selectedOptions = computed(() => {
    if (props.multiple && Array.isArray(model.value)) {
      return normalizedOptions.value.filter((o) => model.value.includes(o.value));
    }
    const opt = normalizedOptions.value.find((o) => o.value === model.value);
  ```
  触发条件是远程搜索：`allow-search` 加 `:filter-option="false"`，由外部替换 `options`。以官方 demo（`app/components/reborn/examples/reborn-select/RebornSelectDemo.vue:186-218、487-489`）为例：
  1. 搜「30」，选中「城市站点 30」。
  2. 单选选中即收起，触发 `visible-change(false)`，demo 把 options 还原成前 8 条。
  3. 已选值 `city-30` 不在列表里，`selectedOptions` 变成空数组，触发器回到占位符，但 `v-model` 仍然是 `city-30`。

  多选更直接：选完再搜别的关键词，之前的标签立刻从触发器上消失。用户既看不到、也删不掉这些已选项。
- 改法：维护一份「已选项缓存」，展示优先取当前 options，取不到时回落到缓存：
  ```ts
  /** 已选项缓存：远程搜索替换 options 后仍能回显 */
  const selectedCache = shallowRef(new Map<any, SelectOption>());
  function remember(list: SelectOption[]) { /* 把命中 model 的项写入新的 Map 再赋值 */ }
  watch(normalizedOptions, remember, { immediate: true });
  // selectOption 时同步写入；selectedOptions 先查 normalizedOptions，再查 selectedCache
  ```
  这和 Element Plus 的 `cachedOptions` 是同一思路。清空和 `remove-tag` 时同步清理缓存。
- 影响：
  - 不改 API。
  - UniApp 端 `RebornSelect` 是 picker 列实现，结构不同，是否有同类问题由 U 分片判断。
  - 要回归 `clearable`、`remove-tag`、`multiple-limit`、`collapse-tags`。

### [高] RebornSwitch：键盘聚焦后按空格只翻转了隐藏 checkbox，绑定值不变、不发事件
- 位置：
  - `app/components/reborn/ui/reborn-switch/RebornSwitch.vue:262`（`label @click="handleClick"`）
  - `app/components/reborn/ui/reborn-switch/RebornSwitch.vue:270-273`（`input @click.stop`）
  - `app/components/reborn/ui/reborn-switch/RebornSwitch.vue:225-245`（`handleClick`）
- 类别：模板 / 数据流
- 依据：`references/component-data-flow.md`「v-model 是双向契约：用户输入必须走到 update:modelValue」。
- 现状：
  ```vue
  <label :class="ui.wrapper({ class: props.class })" ... @click="handleClick">
    <input ref="inputRef" v-bind="inputAttrs" type="checkbox" :checked="isChecked"
      :disabled="isDisabled || props.loading" :class="ui.input()" @click.stop>
  ```
  组件本身是按键盘可用来设计的：input 用 `peer sr-only`，可以 Tab 聚焦；轨道有 `peer-focus-visible` 聚焦环；还 expose 了 `focus()`。

  问题出在按空格时：浏览器会在 input 上派发 click，`@click.stop` 截断冒泡，label 上的 `handleClick` 根本不执行。于是：
  - `update:modelValue` / `change` 都不发，`beforeChange` 也不走；
  - 原生 checkbox 却已经自己翻转了 `checked`，DOM 和 `isChecked` 失步。

  结果是键盘用户无法切换开关。
- 改法：把切换逻辑挂到 input 的 click 上，label 只负责把点击转发给 input（浏览器原生行为），整个组件只有一个入口：
  ```vue
  <label :class="ui.wrapper({ class: props.class })" :data-disabled="isDisabled || props.loading">
    <input ref="inputRef" v-bind="inputAttrs" type="checkbox" :checked="isChecked"
      :disabled="isDisabled || props.loading" :class="ui.input()" @click="handleClick">
  ```
  `handleClick` 第一行同步执行的 `event.preventDefault()`（第 230 行，在 `await beforeChange` 之前）会撤销原生翻转。点击轨道时，label 转发出的 click 落在 input 上，也只处理一次。
- 影响：
  - 不改 API。
  - UniApp 端没有键盘场景，不需要同步。
  - 要回归：异步 `beforeChange` 拦截，`loading` / `disabled` 下不可点，表单 `change` 校验。

### [中] RebornSwitch / RebornRadioGroup：受控绑定被父级置回 undefined 后，回退显示内部旧值
- 位置：
  - `app/components/reborn/ui/reborn-switch/RebornSwitch.vue:134`、`142-145`、`213-216`、`246-253`
  - `app/components/reborn/ui/reborn-radio/RebornRadioGroup.vue:65-68`、`87-92`
- 类别：数据流 / 响应性
- 依据：`references/reactivity.md`「单一数据源」；`references/component-data-flow.md`「v-model 两端要一致」。
- 现状：
  ```ts
  // RebornSwitch.vue
  const val = props.modelValue !== undefined ? props.modelValue : localValue.value;
  watch(() => props.modelValue, (value: any) => { if (value !== undefined) localValue.value = value; });
  // RebornRadioGroup.vue
  const currentValue = computed(() => (model.value !== undefined ? model.value : innerValue.value));
  const updateValue = (value, _ev) => { innerValue.value = value; model.value = value; ... };
  ```
  两个组件都靠「值是不是 undefined」来区分受控和非受控，但受控模式下也会写内部值。

  触发条件：父级把绑定值重置回 `undefined`，比如表单 `resetFields` 恢复到「未赋值」的初值，或业务手动清空。
  - Switch 打开过一次后，父级置为 undefined，组件仍显示打开；
  - RadioGroup 选过一项后，父级置为 undefined，组件仍显示该项选中。
- 改法：绑定值回到 undefined 时，把内部值重置成初始值：
  ```ts
  // RebornSwitch.vue：绑定值被清空时回到非受控初值，而不是停在上一次的受控值
  watch(() => props.modelValue, (value) => {
    localValue.value = value === undefined ? (props.defaultValue ?? props.inactiveValue) : value;
  });
  // RebornRadioGroup.vue
  watch(model, (value) => { if (value === undefined) innerValue.value = props.defaultValue; });
  ```
- 影响：
  - 不改 API。
  - UniApp 端写法完全相同，需要同步修：
    - `packages/uniapp-project/src/components/reborn-switch/RebornSwitch.vue:78、146、176-182`
    - `packages/uniapp-project/src/components/reborn-radio/RebornRadioGroup.vue:67-70、90`
  - 要回归 `defaultValue` 非受控用法和表单重置。

### [中] RebornRate / RebornSlider / RebornSwitch / RebornSku / RebornSplitterPanel：双向绑定手写 modelValue 和 emit，没有用 defineModel
- 位置：
  - `app/components/reborn/ui/reborn-rate/RebornRate.vue:43-44`、`49`、`148`、`358-375`
  - `app/components/reborn/ui/reborn-slider/RebornSlider.vue:26-28`、`107-109`、`210-212`、`479-489`、`712-717`
  - `app/components/reborn/ui/reborn-switch/RebornSwitch.vue:28-33`、`38`、`134`、`213-223`、`246-253`
  - `app/components/reborn/ui/reborn-sku/RebornSku.vue:59`、`66-75`、`141-142`
  - `app/components/reborn/ui/reborn-splitter/RebornSplitterPanel.vue:27-29`、`60-72`
- 类别：数据流
- 依据：项目规则「双向绑定用 defineModel」；`references/component-data-flow.md`「Use defineModel for v-model in Vue 3.4+」。
- 现状：这几个组件都是「`modelValue` prop + 本地镜像 ref + `watch` 回写 + 手动 `emit('update:...')`」的模式。
  - **RebornSku 非受控时点击无反应**：它没有本地镜像，`handleSelect` 只 `emit`。不绑 `v-model` 时，`props.modelValue` 永远是默认的 `{}`，点哪个选项都没有任何反应：
    ```ts
    const newValue = { ...props.modelValue, [option.key]: next };
    emit("update:modelValue", newValue);
    ```
  - **同步逻辑分散**：Rate / Slider / Switch 各维护一份「镜像 + 同步 watch」，代码重复。Switch 因此出现了上一条 undefined 的问题。
  - **RebornSplitterPanel**：`size` 同样手写，问题见下文 SplitterPanel 那一条。
- 改法：
  ```ts
  // RebornRate：读取时夹取，避免越界值进入渲染
  const model = defineModel<number>({ default: 0, get: (v) => clamp(v) });
  // RebornSlider
  const model = defineModel<number>({ default: 0 });
  const values = defineModel<number[]>("values", { default: () => [0, 0] });
  // RebornSku：对象值整体替换
  const model = defineModel<Record<string, any>>({ default: () => ({}) });
  ```
  事件载荷继续用本地算出的新值。按仓库约定，受控绑定下赋值后同步读到的仍是旧值。
- 影响：
  - prop 名和事件名都不变（`modelValue` / `update:modelValue` / `values` / `update:values` / `size` / `update:size`），对外 API 不变。
  - UniApp 端同名的 Rate / Slider / Switch 也是手写写法，建议同批迁移，保持两端实现一致。
  - `RebornRate` 暴露的 `resetCurrentValue`（「撤销未被父级接收的改动」）依赖镜像与 prop 分叉，迁移后要重新确认它的语义，或者改写。
  - 要回归表单校验的触发时机。
