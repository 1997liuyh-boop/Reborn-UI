## 需要处理的问题

### [中] R1 RebornDialog：SSR 下初始打开的对话框在服务端进入模块级弹层栈，永不出栈
- 类型：修复有误
- 原条目：[中] RebornDialog：Esc 与层级不区分最上层，嵌套弹窗按一次 Esc 全部关闭
- 位置：`app/components/reborn/ui/reborn-dialog/RebornDialog.vue:528-531`（doOpen 内 `registerOverlay`）、`:738-764`（`watch(mergedOpen, …, { immediate: true })`）；`app/components/reborn/ui/reborn-drawer/drawer.utils.ts:11-17`（模块级 `overlayStack`）
- 依据：`vue-debug-guides` 的 SSR 平台差异（服务端只执行 setup，不执行 onBeforeUnmount 与过渡回调）；SKILL.md「side effects clean up with their owner」
- 现状：
  ```ts
  watch(mergedOpen, (value) => { if (value) { …; doOpen(); } }, { immediate: true });
  function doOpen() { …; if (!active.value) layer.value = registerOverlay(overlayId, props.zIndex); … }
  ```
  `v-model` 初值为 true 时，immediate 回调在服务端 setup 里同步执行 `doOpen()`，把实例压进 `overlayStack`。出栈只发生在 `onClosed`（过渡 after-leave）和 `onBeforeUnmount`，服务端两者都不执行。于是每渲染一次「默认打开对话框」的页面，Node 进程里的栈就多一项且永不移除。后果：① 服务端常驻内存随请求数增长；② 之后每个请求算出的层级都是 `max(zIndex, 栈顶 + 2)`，服务端输出的 `z-index` 逐次递增，客户端从空栈算出 2400，水合不修补 style，开发环境报 mismatch，生产环境 DOM 留着服务端的大值。Drawer 只在 `onMounted` 之后才打开（`RebornDrawer.vue:353-359`），没有这个问题，是 Dialog 接入共用栈时新带进来的。
- 建议改法：只在客户端入栈。最小改动是在 `doOpen` 里加判断：
  ```ts
  if (!active.value && typeof document !== "undefined") {
    layer.value = registerOverlay(overlayId, props.zIndex);
  }
  ```
  或者在 `drawer.utils.ts` 的 `registerOverlay` 里对 `import.meta.server` 直接返回 `zIndex`、不入栈，Dialog 与 Drawer 一起受保护。

### [中] R2 TextReveal：任何一次组件更新都会还原拆分、重建容器并重播入场动画，不只是插槽内容或参数变化
- 类型：修复有误
- 原条目：[中] TextReveal：SplitText 实例从不 revert，autoSplit 的监听泄漏，改写后的插槽 DOM 与 Vue 冲突
- 位置：`app/components/reborn/ui/text-reveal/TextReveal.vue:71-75`、`:85-87`；文档 `content/2.components/text-animations/text-reveal.md`（Props 表下方的说明）
- 依据：`references/updated-hook-performance.md`（updated 钩子随任何原因的重渲染执行，不能当成「内容变了」的信号）；`references/component-slots.md`（父组件重渲染时，动态插槽会强制子组件更新）
- 现状：
  ```ts
  onBeforeUpdate(() => { destroySplit(); contentKey.value++; });
  onUpdated(createSplit);
  ```
  重播挂在 `onBeforeUpdate` / `onUpdated` 上，触发条件是「本组件发生更新」，而不是文档写的「插槽内容或上述参数变化」。下面几种常见写法都会让与文字无关的父组件重渲染触发整段重播（容器 DOM 整块重建、所有行重新从下方滑入）：
  1. 列表里使用：`<TextReveal v-for="p in paragraphs" :key="p.id">{{ p.text }}</TextReveal>`。插槽引用了 v-for 的作用域变量，编译成动态插槽，父组件每次重渲染都会强制子组件更新；
  2. `class` / `container-class` 传内联数组或对象（`:class="['text-lg', active && 'text-primary']"`），每次渲染都是新引用，props 比较判定为变化；
  3. 插槽里读取了父组件的任意响应式状态，哪怕与文字无关（如悬停态切换的类名）。
  后果是页面上任何不相关的状态变化都会让段落反复闪现入场动画，文档的描述也与实现不符。
- 建议改法：只在真正影响拆分的输入变化时重建。两种做法任选：
  - 收窄触发源：参数用 `watch(() => [props.duration, props.delay, props.stagger], rebuild)`；插槽内容在 `onBeforeUpdate` 里先算出本次插槽的文本签名（例如递归拼接 `slots.default?.()` 的 vnode 文本，或渲染到一个不受 SplitText 改写的隐藏副本里取 `textContent`），与上次相同就跳过 destroy、key 递增与重播；
  - 或者退回原报告的另一种选择：只在 `mounted` 拆分一次，在文档注意事项写明插槽须为静态文本，需要换内容时由使用方改 `:key`。
  无论哪种，都要把文档里「插槽内容或上述参数变化时重播」改成与实现一致的说法。

### [低] R3 RebornDropdown：options 的 key 混用「原始值」与「下标」，值重复或数字值与对象项下标相同时产生重复 key
- 类型：修复有误
- 原条目：[低] 列表 key 不稳定（Dropdown 部分；Draggable 部分已修好）
- 位置：`app/components/reborn/ui/reborn-dropdown/RebornDropdown.vue:336`
- 依据：`references/sfc.md`「Always provide a stable :key」（key 必须在兄弟节点间唯一）
- 现状：
  ```vue
  v-for="(option, index) in options" :key="typeof option.value === 'object' ? index : option.value"
  ```
  修复前用下标，key 一定唯一；现在两种情况会撞 key：① 两个选项的 value 相同（例如两个入口都回传 `'share'`）；② 数字 value 与某个对象 value 的下标相同（`[{ value: 1 }, { value: { id: 9 } }]` 里第二项的 key 是下标 1）。`null` 的 `typeof` 也是 `'object'`，会走下标分支，同样可能与数字值相撞。重复 key 时开发环境告警，patch 会错位复用 RebornDoption 的 DOM。
- 建议改法：两类 key 放进不同命名空间，例如 `:key="typeof option.value === 'object' && option.value !== null ? \`i:${index}\` : \`v:${String(option.value)}\`"`；或者给 `DropdownOption` 加一个可选的 `key` 字段优先使用，并在文档注明 value 需唯一。

### [低] R4 RebornTree：内部写入标记按内容比对且从不清空，外部写入与上次内部写入内容相同时 autoExpandParent 被跳过
- 类型：部分修复
- 原条目：[低] RebornTree：internalExpandWrite 标记在父组件不回写时会滞留，吞掉下一次外部变更
- 位置：`app/components/reborn/ui/reborn-tree/RebornTree.vue:292-305`、`:322-333`
- 依据：`references/component-data-flow.md`（受控组件要区分「自己写入的回流」与「外部写入」，判定不能吞掉外部意图）
- 现状：
  ```ts
  if (toRaw(keys) === last) return true;
  return keys.length === last.length && keys.every((key, index) => key === last[index]);
  ```
  布尔标记换成了「最后一次内部写入的数组」，但识别出回流后不清空，此后任何一次内容与它相同的外部写入都会被当成回流跳过。触发条件：开启 `autoExpandParent`，用户先收起父节点 P（内部写入 `[C]`，C 是 P 的子节点），之后父组件用新数组写回相同内容（例如从快照恢复 `expandedKeys.value = [...saved]`），期望补全父链把 P 展开，结果 P 保持收起。概率很低，但正是这条要消除的「吞掉外部变更」。
- 建议改法：回流被识别后立即清空标记，只跳过紧随其后的那一次回流：
  ```ts
  if (isInternalExpandWrite(val)) { lastInternalExpandKeys = null; return; }
  ```
  父组件拒绝回写时标记会留到下一次内部写入被覆盖，内容不同的外部写入照常处理。
