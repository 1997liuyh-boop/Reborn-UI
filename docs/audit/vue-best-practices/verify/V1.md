## 需要处理的问题

### [中] MultiStepLoader：`loading` 的 watcher 加了 `immediate: true` 后，服务端渲染会起定时器并执行步骤 action
- 类型：修复有误
- 原条目：[中] M15 MultiStepLoader：初始 loading=true 时不启动；关闭或卸载后异步步骤链仍继续推进
- 位置：`app/components/reborn/ui/multi-step-loader/MultiStepLoader.vue:77-83`、`:66-73`、`:44-63`
- 依据：`references/reactivity.md`「Use watchers for side effects」与同分片 M13（HyperText）口径——副作用只在客户端挂载后启动；`vue-debug-guides` 的 `lifecycle-ssr-awareness`（SSR 中 `immediate` watcher 的回调会执行一次，`onUnmounted` 不会执行）
- 现状：
  ```ts
  watch(() => props.loading, (loading) => {
    stop();
    if (!loading) return;
    currentState.value = 0; isLastStepComplete.value = false;
    processCurrentStep(); // → setTimeout → proceedToNextStep → await step.action?.()
  }, { immediate: true });
  ```
  首屏 `loading` 为 true 且组件在 SSR 页面中时，服务端渲染阶段就会 `setTimeout`，随后在服务端依次执行每一步的 `action`、`emit("state-change")` / `emit("complete")`；服务端没有卸载钩子，这条定时器链一直走到最后一步。客户端水合后同一 watcher 再跑一遍，用户的 `action`（文档示例里就是 `fetch('/api/data')`）被执行两次，其中一次发生在服务端请求里。已用临时 SSR 脚本确认：两步流程渲染后服务端记录到 `action` 调用 `["a","b"]` 与事件 `[1,"complete"]`。现有 `tests/multi-step-loader` 的 SSR 用例只用了 `async: true` 步骤，覆盖不到这条路径。
- 建议改法：保留「首次 loading=true 自动开始」，但把启动门控到挂载后，和 AnimatedTestimonials / Focus 的写法一致：
  ```ts
  const mounted = useMounted();
  watch(() => props.loading && mounted.value, (running) => {
    stop();
    if (!running) return;
    currentState.value = 0;
    isLastStepComplete.value = false;
    processCurrentStep();
  }, { immediate: true });
  ```
  并给 SSR 用例补一个非 async、带 action 的步骤，断言服务端渲染后 action 未被调用。

### [中] RebornAffix：resize 改成「只夹边」后，传 `right` / `top` 的按钮在窗口尺寸变化后不再贴靠，且与 UniApp 端 resize 行为相反
- 类型：修复有误
- 原条目：[中] M20 RebornAffix：定位 props 只在初始化读取；挂载与窗口变化时无视 noSnapping 强制吸附
- 位置：`app/components/reborn/ui/reborn-affix/RebornAffix.vue:48-58`；对照 `packages/uniapp-project/src/components/reborn-affix/RebornAffix.vue:56-67`
- 依据：`references/reactivity.md`「use watchers for side effects」（副作用的触发源要覆盖所有影响结果的量）；项目规则「Web 与 UniApp 同名组件行为尽量一致」
- 现状：
  ```ts
  watch(() => [props.left, props.right, props.top, props.bottom, props.size], resetPosition);
  watch([screenWidth, screenHeight], () => { if (hydrated.value) clampPosition(); });
  ```
  内部只存 `left` / `bottom` 坐标。`right=20`、窗口宽 1200 时 `x = 1140`；窗口拉宽到 1600 后只夹边，`x` 仍是 1140，按钮离右缘变成 420px。整改前 resize 会强制吸附，按钮至少还在右侧；现在用户从未拖动过，按钮也会随窗口变化漂到中间（拖拽桌面浏览器窗口、打开 DevTools、平板旋转都会触发）。`top` 锚定同理。UniApp 端整改后在 `uni.onWindowResize` 里调用 `resetPosition()`，按 props 重新锚定、丢弃拖拽位置；两端在同一场景下一个保留拖拽位置但丢锚点，一个保留锚点但丢拖拽位置，原条目要求的「两端对齐」没有达成。
- 建议改法：两端统一为「未拖动过时按 props 重新锚定，拖动过后只夹边」：
  ```ts
  let userMoved = false;
  function onPointerUp(e: PointerEvent) { /* … */ userMoved = true; }
  watch(() => [props.left, props.right, props.top, props.bottom, props.size], () => { userMoved = false; resetPosition(); });
  watch([screenWidth, screenHeight], () => {
    if (!hydrated.value) return;
    if (userMoved) clampPosition(); else resetPosition();
  });
  ```
  UniApp 端的 `onWindowResize` 回调按同一规则改（拖动过后只夹边），并在文档注意事项写明 resize 的行为。

### [中] IInput / Compare / BalanceSlider / RebornAlert：声明了 `defineModel` 却在受控分支绕开它，靠 `getCurrentInstance()` 读 `vnode.props` 手动派发
- 类型：修复有误
- 原条目：[低] L03 ColorPicker / MorphingTabs / Lens / Compare / IInput：手写双向绑定，未用 defineModel（同模式还出现在本分片 M18 的 BalanceSlider 与整改轮次新加的 RebornAlert `show`）
- 位置：`app/components/reborn/ui/input/IInput.vue:19-41`；`app/components/reborn/ui/compare/Compare.vue:34-59`；`app/components/reborn/ui/balance-slider/BalanceSlider.vue:29-50`；`app/components/reborn/ui/reborn-alert/RebornAlert.vue:90-118`
- 依据：`references/component-data-flow.md`「Use `defineModel` by default for component bindings」；`SKILL.md`「Encapsulate reactive bookkeeping」「Public contracts are typed and hide internals」；Vue 文档把 `getCurrentInstance` 定位为内部 API，不建议业务代码使用
- 现状：
  ```ts
  const model = defineModel<string | number | null>();
  const instance = getCurrentInstance()!;
  const modelProps = shallowRef(instance.vnode.props ?? {});
  onBeforeUpdate(() => { modelProps.value = { ...instance.vnode.props }; });
  const controlled = computed(() => Object.hasOwn(modelProps.value, "modelValue") || Object.hasOwn(modelProps.value, "model-value"));
  const modelValue = computed({
    get: () => controlled.value ? instance.props.modelValue : localValue.value,
    set: (v) => { if (controlled.value) emit("update:modelValue", v); else { localValue.value = v; model.value = v; } },
  });
  ```
  目的是区分「未传」与「显式 undefined / null」，让显式空值复位到初值。常见用法下行为正确（49 个定向用例通过），但：① `defineModel` 的返回值在受控分支完全不用，又用 `defineEmits` 重复声明 `update:xxx`，模型逻辑实际仍是手写的，原条目要解决的问题换了个形式留下；② 依赖 `instance.vnode.props`、`instance.props` 与 `onBeforeUpdate` 同步时机等内部细节，Vue 小版本调整 `useModel` / 实例结构时需要逐个回归；③ 同一段 8～10 行代码在本分片 4 个文件里各抄一份（全仓库 Web 组件还有 RebornBadge、RebornCollapse、RebornCheckbox 等十余处），而 UniApp 端已经抽成了 `composables/useRawProp.ts` + `useBooleanModel.ts`，两端写法也不一致；④ RebornAlert 在改动后留下孤立注释与空行（`RebornAlert.vue:117-119`）。
- 建议改法：保留「显式空值复位」语义的前提下，把这段逻辑收进 `app/composables/` 的一个组合式函数（与 UniApp 端 `useRawProp` / `useBooleanModel` 对齐命名与语义），组件里只写一行，例如
  ```ts
  const modelValue = useControllableModel<string | number | null>("modelValue", {
    fallback: () => localValue.value, // 未绑定时
    empty: () => undefined,            // 显式空值时
  });
  ```
  并删掉组件内重复的 `defineEmits('update:xxx')`。若评估后不需要区分显式空值，直接回到纯 `defineModel` + 本地兜底（`model.value ?? local.value`）即可，不必读实例内部。

### [低] ContainerTextFlip：只在单词下标变化时重测宽度，`words` 换了或变短时外框宽度与下标不更新
- 类型：新问题
- 原条目：无
- 位置：`app/components/reborn/ui/container-text-flip/ContainerTextFlip.vue:38-46`、`:51`、`:75`
- 依据：`references/reactivity.md`「Use watchers for side effects」——watch 源要覆盖所有影响副作用的量
- 现状：
  ```ts
  onMounted(measure);
  watch(currentWordIndex, measure, { flush: "post" });
  ```
  父组件替换 `words`（演练场改单词、换语言）时 `currentWordIndex` 不变，外框宽度停留在旧单词的测量值，直到下一次轮换；新数组比当前下标短时，`words[currentWordIndex]` 为 `undefined`，外框内容为空一整个 `interval`。
- 建议改法：`watch([currentWordIndex, () => props.words], measure, { flush: "post" })`，并在 `words` 变化时把下标夹回 `currentWordIndex.value %= props.words.length || 1`。

### [低] Meteors：为提供单一根节点用了 `display: contents` 的 span，透传的非继承样式（opacity、transform 等）不产生视觉效果
