### [低] 主题色插件：服务端 `useCookie` 带默认值，未选过主题色的访客每个 SSR 响应都被写入 `Set-Cookie`
- 类型：新问题
- 原条目：无（由 [高] AppThemePicker 的修法引入）
- 位置：`app/plugins/theme-color.ts:4`（V7 范围文件，问题表现为本分片的全站页面响应）
- 依据：`vue-debug-guides/reference/lifecycle-ssr-awareness.md`：服务端执行的副作用要有意为之；Nuxt `useCookie` 在服务端渲染结束时，若值与请求 cookie 不等就写 `Set-Cookie`。
- 现状：
  ```ts
  const cookie = useCookie<string>('theme-color', { default: () => 'blue' })
  ```
  选择器原来在 `<ClientOnly>` 里，服务端从不执行 `useCookie`；挪进全站插件后，服务端对没有 cookie 的请求取默认值 `'blue'`，与请求里的「无」不相等，于是写回。实测 `curl -D - http://127.0.0.1:3000/getting-started` 响应头带 `set-cookie: theme-color=blue; Path=/`。预渲染的静态页不受影响；但所有走 SSR 的路由（以及将来配置 `swr` / `isr` 缓存的路由）对新访客都会带 `Set-Cookie`，共享缓存 / CDN 通常因此不缓存该响应，并且用户「从未选择」与「选了品牌蓝」不再可区分。
- 建议改法：插件里不给 cookie 默认值，只在用户真正切换时写入：
  ```ts
  const cookie = useCookie<string | undefined>('theme-color')
  themeColor.value = normalizeThemeColor(cookie.value)
  watch(themeColor, (value) => { cookie.value = normalizeThemeColor(value) })
  ```
  `normalizeThemeColor` 已对 `undefined` 回落 `'blue'`，首屏与阻塞脚本的行为不变。

- 依据：`references/component-async.md`：异步组件定义应在模块作用域创建一次；`vue-debug-guides/reference/perf-props-stability-update-optimization.md`：传给子组件的对象应保持稳定引用。
- 现状：
  ```ts
  const mdcComponents: Record<string, DefineComponent<any, any, any>> = {
    pre: defineAsyncComponent(() => import('docus/modules/assistant/runtime/components/AssistantPreStream.vue')) as DefineComponent<any, any, any>,
  }
  ```
  这段原来在抽屉 setup 里只创建一次；搬进单条消息组件后，每条消息实例都新建一个异步组件包装和一个 `components` 对象。模块加载有缓存，不会重复下载，但每个 `MDCCached` 拿到的 `pre` 是不同的组件定义，代码块组件无法跨消息复用，历史越长多出的定义越多，也和本次「把每条消息的 props 稳定下来」的目的相悖。
- 建议改法：把 `mdcComponents`（以及 `parserOptions`）移到同文件的普通 `<script lang="ts">` 块（与 `<script setup>` 并存）或一个小模块里导出，所有消息共用同一份对象。

### [低] DemoStage：iframe 主题同步自己硬编码「blue → brand」，没有复用主题色表
- 类型：新问题
- 原条目：无（由 [高] AppThemePicker 改法第 3 点引入）
- 位置：`app/components/common/demo-stage/DemoStage.vue:49`
- 依据：技能 Core Principles「one source of truth, derive everything else」。
- 现状：
  ```ts
  doc.documentElement.dataset.themeColor = themeColor.value === 'blue' ? 'brand' : themeColor.value
  ```
  色系名到预设名的映射在 `app/utils/themeColor.ts:2-7` 已有唯一定义，插件（`theme-color.ts:10`）与选择器都从那里查；这里另写了一份三元表达式。今天结果一致，但以后新增一个预设名与色系名不同的色系时，文档页外层会切对、设备档 iframe 里却写成不存在的预设，示例回落到默认色。
- 建议改法：`import { themeColors } from '~/utils/themeColor'`，写 `themeColors.find(c => c.name === themeColor.value)?.preset ?? 'brand'`；或在 `themeColor.ts` 导出 `themeColorPreset(name)` 供插件、DemoStage 共用。
