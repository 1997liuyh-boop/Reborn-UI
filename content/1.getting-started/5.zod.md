# Zod 模式验证

Zod 是一个以 TypeScript 为先的模式声明和验证库。旨在弥补 TypeScript 仅在编译时有效的不足，提供运行时的校验能力。

## 1. 基础类型验证

最简单的用法是验证基础类型，例如字符串或数字。

### 示例代码

```ts
import { z } from "zod";

/** 定义 Schema：允许 string 或 number */
const StringOrNumber = z.union([z.string(), z.number()]);

// 测试数据
const input1 = "hello";
const input2 = 123;
const input3 = true; // ❌ 错误类型

// 验证
const result1 = StringOrNumber.safeParse(input1); // ✅ Success
const result3 = StringOrNumber.safeParse(input3); // ❌ Fail
```

### 输入与输出

| 输入值 (Input) | 验证结果 (Output) | 说明 |
| :--- | :--- | :--- |
| `"hello"` | `{ success: true, data: "hello" }` | 符合 `string` 类型 |
| `123` | `{ success: true, data: 123 }` | 符合 `number` 类型 |
| `true` | `{ success: false, error: ... }` | `boolean` 不在允许范围内 |

## 2. 对象模式与区分联合 (Discriminated Unions)

处理复杂数据结构时，推荐使用 `z.object` 和 `z.discriminatedUnion`。区分联合（Discriminated Union）能提供更精准的类型推断和报错信息，特别是当对象中有共同的 "标签" 字段（如 `kind`）时。

### 示例代码

```ts
/** 定义圆形 */
const Circle = z.object({
  kind: z.literal("circle"),
  radius: z.number().positive("radius 必须 > 0"),
});

/** 定义正方形 */
const Square = z.object({
  kind: z.literal("square"),
  side: z.number().positive("side 必须 > 0"),
});

/** 
 * 定义形状联合
 * 推荐用 discriminatedUnion 而不是 ordinary union
 * 只要判断了 kind，TS 就能自动收窄类型
 */
const Shape = z.discriminatedUnion("kind", [Circle, Square]);
```

### 验证场景演示

#### 场景 A: 合法数据

```ts
const val = { kind: "circle", radius: 10 };
const result = Shape.safeParse(val);
// output: { success: true, data: { kind: "circle", radius: 10 } }
```

#### 场景 B: 业务逻辑校验失败

```ts
const val = { kind: "circle", radius: -1 };
const result = Shape.safeParse(val);
// output: { success: false, error: [Issues...] }
// 错误详情: radius 必须 > 0
```

#### 场景 C: 结构错误

```ts
const val = { kind: "triangle", side: 3 }; 
const result = Shape.safeParse(val);
// output: { success: false, error: ... }
// 错误详情: Invalid discriminator value. Expected 'circle' | 'square'
```

## 3. TypeScript 类型推断与收窄

Zod 的杀手锏功能：**一次定义，处处使用**。你不需要单独写 TypeScript 接口，直接从 Schema 推断即可。

### 类型推导

```ts
/** 直接从 Shape Schema 推断类型 */
type TShape = z.infer<typeof Shape>;

// 等价于：
// type TShape = 
//   | { kind: "circle"; radius: number } 
//   | { kind: "square"; side: number }
```

### 类型收窄 (Type Narrowing)

在函数中使用推断出的类型时，TypeScript 会根据 `kind` 字段自动收窄类型，让你能够安全地访问特定属性（如 `radius` 或 `side`）。

```ts
function calcArea(shape: TShape) {
  // 此时 shape 是 TShape 联合类型
  
  if (shape.kind === "circle") {
    // ✅ 在这里，TS 知道 shape 是 Circle 类型
    // 可以安全访问 .radius
    return Math.PI * shape.radius ** 2;
  }
  
  // ✅ 在这里，TS 知道 shape 只能是 Square 类型
  // 可以安全访问 .side
  return shape.side ** 2;
}

// 实际使用
const myCircle = { kind: "circle", radius: 10 };
console.log("Area:", calcArea(Shape.parse(myCircle)));
```

## 4. 实战场景：复杂表单验证

在真实业务中，我们经常需要处理数据转换、正则校验以及字段间的依赖关系。以下是一个包含复杂逻辑的表单验证示例。

### 综合示例

[在线体验](https://codesandbox.io/p/sandbox/lygh93)

```ts
// 模拟响应式数据（Vue Ref 或其他状态）
const newData = { 
  price: 100, 
  content: [] 
};

// 正则校验：密码复杂度
const passwordSchema = z
  .string()
  .min(8, "密码至少8位")
  .regex(
    /^(?=.*[a-z])(?=.*[A-Z])(?=.*\W).+$/,
    "需包含大小写字母和特殊符号"
  );

const baseSchema = z.object({
  // 1. 自定义校验：邮箱后缀限制
  email: z
    .email("邮箱格式不正确")
    .refine(
      (val) => val.endsWith("@qq.com") || val.endsWith("@163.com"),
      "仅支持 QQ 或 163 邮箱"
    ),

  // 2. 密码复杂度
  password: passwordSchema,

  // 3. 数据预处理 (Preprocess)：将字符串转数字后再校验
  confirmPassword: passwordSchema.refine(
    (val) => val === form.value.password,
    "两次密码输入不一致"
  ),

  // 4. 联合类型与 Optional
  telPhone: z
    .union([
      z.literal(""),
      z.string().regex(/^137\d{8}$/, "手机号格式不正确"),
    ])
    .optional(),

  price: z.preprocess(
    (val) => Number(val),
    z.number().refine(
      (n) => /^\d+(\.\d{1,2})?$/.test(n.toString()),
      "最多只能保留两位小数"
    )
  ),

  code: z.string().length(4, "验证码必须为 4 位"),

  // 5. 动态校验：依赖其他字段的值
  content: z
    .array(z.string())
    .refine(
      (val) => (newData.price > 200 ? val.length > 2 : true),
      "价格大于200时，内容长度必须大于2"
    ),

  // 6. 数组对象与整体逻辑校验
  list: z
    .array(
      z.object({
        name: z.string().min(2, "Name 最少两个字符"),
        no: z.coerce.number(), // z.coerce 也可以强制转换类型
        money: z.coerce.number(),
      })
    )
    .min(3, "List 长度不能小于 3")
    .refine(
      (items) => {
        // 逻辑：校验 no 和 money 是否递增
        for (let i = 1; i < items.length; i++) {
          if (
            items[i].no <= items[i - 1].no ||
            items[i].money <= items[i - 1].money
          ) {
            return false;
          }
        }
        return true;
      },
      {
        message: "no 和 money 必须是递增的",
      }
    ),
});
```

### 关键技巧解析

1.  **`z.refine`**: 最强大的工具，允许你编写任意 JS 函数进行验证。
    *   *用途*：检查邮箱后缀、检查数组是否排序、检查字段间依赖。
2.  **`z.preprocess` / `z.coerce`**: 处理原始数据类型不匹配的问题。
    *   *场景*：输入框的值通常是 string，但 Schema 需要 number。
3.  **`z.pick`**: 从大 Schema 中提取局部 Schema。
    *   *场景*：单独验证表单中的某一个字段。
